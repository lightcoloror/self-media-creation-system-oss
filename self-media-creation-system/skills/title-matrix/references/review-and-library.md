# 诊断与复盘

## 诊断现有标题

先说主要问题，再给实际替换文本。对每个候选核对：

1. 读者会预期看到什么？
2. 正文对应哪一段？缺证据就收窄或标记 `needs_source`。
3. 相比原题改了什么，为什么更符合本篇目标？这是编辑假设，不是效果事实。
4. 新题是否新增事实、夸大程度、泛化个案，或引出正文没有回答的问题？

修改正文以兑现标题时，记录改前改后，重跑受影响的现有门。不能把已拒绝的主张换个近义词重新放入候选。只有保留决定时也可完成诊断，但必须写明“保留，未改稿”及理由。

## 发布后复盘

复用已有发布/指标记录，不在 Skill 内建案例库，也不默认采集或写入外部平台。关联作品、实际标题、平台账号、正文/封面版本、发布时间、观测窗口、数据来源和缺失项。

- 优先比较同账号、近似题材/形式和同样窗口。改了正文、封面或分发也要登记，不能把全部变化归因于标题。
- 播放、曝光、点击率、完播、关注、咨询和转化是不同指标；分母缺失就不推算。粉丝总量不能证明哪条内容带来涨粉。
- 区分实测结果、关联观察和下一次假设。少量案例不宣称稳定规律；跨账号差异不能直接证明可复制效果。
- 用户已判定不可信的数据排除出效果结论；本项目快手历史导出曾被用户指出不可信，除非来源重新核验，不据此推荐标题。
- 上游未提供可复核原始样本的“高频词/爆款规律”只可作灵感，不能当已验证证据。

输出一项有根据的下一次试验即可；不为了凑矩阵安排大量发布，也不擅自改已发布标题。
