# 视频变声与面部打码双门设计

> 状态：已确认并落地  
> 时间：2026-08-24 23:47:35 +08:00  
> 执行者：Codex（GPT-5.6 Sol）  
> 边界：只记录决定、校验哈希和生成局部重做清单；不自动识别客户身份、不联系客户、不渲染媒体、不发布。

## 已确认需求

1. 素材进入制作流程时，按匿名 `subject_ref` 决定该人物是否变声、是否面部打码。
2. 没有明确决定时可以先做内部预览，但不能成为发布就绪候选。
3. 客户看到候选后，由人工记录确认、撤回或精确到秒的修改要求。
4. 发布前临时变卦时，复用本地已有的 EDL、说话人片段、人脸轨迹、打码、变声和动效配方，只替换受影响时间窗。
5. 变声默认保持原性别与相近音域，并保留 F0／语调；粤语优先使用同语言、同方言参考声线。
6. 人脸轨迹必须先由人工绑定到匿名人物角色和身份参照；检测到人脸不等于确认了人物身份。
7. 面部处理必须覆盖最终画面中的实际可见窗口，并逐窗口检查进入前、第一帧、中点、最后一帧和离开后。

## 设计结论

采用“版本化双门 + 发布前判定”，不把客户沟通、视频渲染和发布塞进一个自动任务。

```text
本地素材与编辑清单
  → 初始人物处理决定
      ├─ 明确：按决定制作客户候选
      └─ 未决定：只制作内部预览
  → 身份绑定与隐私渲染质检
      ├─ 目标人物全覆盖、非目标人物无误伤：继续
      └─ 身份未定／漏打／误伤／窗口缺失：拒绝当前候选
  → 人工记录客户对精确候选哈希的确认
      ├─ 确认：进入发布前判定
      ├─ 变更：生成局部重做清单
      └─ 撤回：停止
  → 发布前判定
      ├─ exact decision + exact candidate + confirmed → 可交人工发布门
      └─ 其他状态 → 内部预览／局部重做／停止
```

“可交人工发布门”只说明身份、窗口、渲染质检和客户确认合同完整，永远不代表自动发布。

## 为什么引用本地配方而不复制参数

- 秒数、说话人分段、人脸轨迹和动效时间轴是局部重算的稳定定位数据。
- 人脸轨迹只是几何／时序证据；匿名身份参照和人物角色才是“应打谁”的决策证据，两者必须同时存在。
- 变声、马赛克和动效参数继续由本地配方目录管理；流程合同只保存配方引用和哈希绑定。
- 未列入 `changed_windows` 的时间窗统一冻结，避免一次临时改动触发整片回炉。
- 每类变更只使相应锁和检查失效，例如变声重验响度与字幕时序，打码重验隐私与保护区域，动效重验画面和动效时序。

## 不能自动推断的内容

- 人物是谁、客户是谁、是否同意公开。
- 检测到的某张脸属于客户、采访者还是其他人物。该绑定必须由人工确认，系统不得根据画面位置、说话顺序或出镜时长猜测。
- “没有回复”不等于同意，也不等于选择保留原声或露脸。
- 客户确认过旧版本，不等于确认新候选；任一候选或决定哈希变化，都必须重新确认。
- 变声工具能跨性别转换，不代表该效果适合交付。默认合同只接受 `convert_same_gender_range`。

## 采用的现有能力

- 既有 `mvp-video-pipeline` 继续负责视频候选制作。
- 既有 `context-efficient-rework` 继续负责受影响窗口的有限返工。
- 所有按时间段的人审继续走 VKP `targeted-review`，不新增第二套播放器。
- 新增的 `video_privacy_treatment.py` 只做本地、确定性的合同与哈希判定。

## 身份与边界门的失败关闭条件

以下任一情况出现时，候选只能返工，不能交客户确认或发布：

- 需要打码的人物没有身份参照或角色确认；
- 同一人脸轨迹被分配给多个人物；
- 任一实际可见窗口没有对应质检记录；
- 目标人物的第一帧、中点或最后一帧未被覆盖；
- 人物进入前或离开后仍误伤采访者、创作者或其他非目标人物；
- 授权提示的显示窗口与客户实际出镜窗口不一致；
- 隐私质检所绑定的候选哈希已经变化。

## 2026-08-24 补充决策记录

- 意图：把“打码准确、无遗漏、无误伤”从经验要求提升为可验证合同。
- 决策：第一道门不再只检查客户选择，还必须检查人物身份绑定、最终画面窗口和五点渲染质检。
- 理由：这三类证据分别回答“要打谁”“什么时候能看到”“实际有没有打对”，缺一项都可能产生隐私事故。
- 证据：质子治疗系列第一次处理曾打到采访者而漏掉受访者；角色绑定和逐窗口五点复核能够直接发现该类错误。
- 生效范围：`case-video-candidate` 及所有复用其隐私处理合同的客户案例视频。
