# Title Matrix：本地自媒体适配

## 先确定任务与版本

- 复用本篇已有路线卡、事实卡、受众、唯一目标、个人口吻、对标采用/拒绝记录与正文，不另建流程或事实库。
- 在自媒体项目中，读取当前 `routing-binding.v1.json` 指向的规范运行册；本地入口是 `<workspace>/self-media-creation-system/skill-invocation-runbook.md`。优先级与制作门沿用项目。
- 正式标题筛选在正文结构、情绪、事实及适用合规问题关闭、作者确认相应正文版本后进行。标题不能代替上游修复。
- 选题／提纲阶段默认允许早期探索：将人群处境、观看所得、暂定标题、封面文字主张、首句与正文／事实支撑一起比较。标记 `exploratory-candidate`、版本与缺口；仅写封面主张，不提前制图，不运行冻结后 Hook、不推进制作或签发通过回执。承诺无法兑现时回到角度或缩小承诺。
- 明确是生成、诊断、比较还是发布后复盘。缺正文时先读用户提供的正文路径；仅有题目则标记待兑现，不杜撰故事。

## 从正文生成，而不是从强度生成

本地适配更新：2026-10-09 18:50:58 +08:00｜Codex（GPT-6）。早期探索沿用路由卡及争点候选；下列正式筛选继续要求正文问题关闭和相应作者确认，不能用探索候选替代。

1. 摘出内容核心：给谁看、讲哪件具体事、有什么行动/代价/转折/结果，以及不承诺什么。只使用正文与已确认事实。
2. 选择与本篇目标有关的角度，如具体投入、遇到的困难、前后变化、读者已有问题。角度数量按任务需要；普通单篇给 3–5 个有区别的候选，用户指定数量优先。
3. 每个候选逐项检查人物、身份、数字、动作、结果、范围和程度。以普通读者会理解成什么为准：数字没变，措辞也可能夸大；作者有情绪也不自动证明客观结论。
4. 标记兑现位置：开头说明读者将看到什么，正文哪里真的兑现。没有固定“十秒”判定；承诺迟迟不落地时，收窄标题或给出实际开头修改，再回到适用审核。
5. 删除虚构的崩溃、欺骗、资格背书、万能答案、承保/赔付保证和健康恐惧。标题承诺“攻略/答案/清单”时正文必须确实提供；个人经历不要包装成人人适用的方案。
6. 按受众识别、具体性、好奇缺口、正文兑现与口吻比较，推荐一个并说清取舍。不用伪精确评分、爆款概率或无证据的涨粉预测。原题更好时明确保留理由，不强改。
