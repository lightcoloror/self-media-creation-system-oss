# 自媒体视觉字号硬门禁

## 结论

字号不再是审美建议或人工复核备注，而是所有含文字视觉产物的发布前硬门禁。封面、图文卡片、文章 HTML、竖屏 HTML／信息动效、字幕、署名和免责声明，都必须按输出 profile 与文字角色检查实际渲染后的字号。任何角色低于门槛、检测证据缺失或过期、目标手机预览不可读、文字溢出／截断／碰撞，都保持 `candidate_only` 并停止下游。

## 唯一策略与职责

- 数值策略唯一来源：`<workspace>/ai-video-tools-20260708/mvp-video-pipeline/src/video_creation_pipeline/policies/typography-gates.v1.json`。
- MVP Video 负责封面、竖屏视频信息动效、字幕及声明等视频画面的策略投影、实际渲染和门禁回执。
- Content Studio 读取同一策略，负责图文卡片与文章 HTML 的 DOM computed-style 检查；不得复制另一份阈值。
- `lucas-case-cover-craft` 与个人视觉系统负责角色、构图、品牌和人工小图判断，不拥有第二套数值策略。
- self-media creation system 只验证 owner 回执、哈希和发布边界，不新建渲染器或字号检测器。

## 文字角色

每个可见文本节点必须显式提供 `data-font-role`，或由 owner 使用已记录的安全 fallback 分类。角色至少包括：

- `primary_headline`：封面主文案、页面主标题；
- `scene_title`：场景标题、章节标题；
- `body`：通栏正文；
- `multi_column_body`：卡片、并列结构与多栏正文；
- `key_number`：金额、比例、步骤数字及其他主要数值；
- `label`：短标签、时间线节点、结构说明；
- `subtitle`：逐字字幕；
- `attribution`：机构、姓名、执业编号等署名；
- `disclosure`：案例、AI、医疗和理赔边界声明。

不能把承担阅读任务的文字伪装成 `attribution` 或 `disclosure` 来绕过较高门槛。无角色且无法安全归类时失败关闭。

## 固定执行顺序

1. 先选输出 profile，再读取策略，不从现有 CSS 反推门槛。
2. 在视觉计划中写明各文本角色；门槛只规定最低值，不是统一固定字号。实际字号仍须根据可用空间、字数和视觉层级自适应，短文案和重点数字应主动高于门槛，任何自适应算法都不得降到门槛以下。
3. HTML 产物渲染后读取 computed style、文本框尺寸、实际可见性和 overflow；Remotion／视频产物则绑定 renderer 实际字号参数并检查最终关键帧的可见性、溢出、截断和碰撞。不能只检查设计稿或未执行的 CSS／TS 常量。
4. 绑定策略文件 SHA-256、输入计划 SHA-256 和成品 SHA-256，生成 typography receipt。
5. 自动门通过后，再以固定信息流尺寸做一秒扫视与三秒阅读。人工预览不能替代自动门，自动门也不能替代实际手机可读性。
6. 任一失败按“删次要信息 → 调换行和层级 → 放大文字或证据 → 移动主体／改变构图 → 必要时更换视觉路线”返工；禁止为了塞下内容继续缩小。
7. 只改文字或版式时，重跑受影响的比例／时间窗口及其下游碰撞检查；未受影响素材不重复渲染。

## 各流程的阻断点

- 图文创作：正文冻结后、导出发布图前，必须取得 Content Studio typography receipt。
- 封面：每个 16:9、4:3、3:4、9:16 profile 独立排版、独立门禁；一个比例通过不能替另一个比例放行。
- 竖屏 HTML／信息动效：在合成进视频前检查；不得等到字幕和水印完成后才发现字号过小。
- 字幕：以最终音频时间轴生成后检查实际 ASS／烧录结果；字幕门槛与卡片正文门槛分开。
- 署名与声明：允许低于主文案，但仍有独立最低字号与安全区，不得小到手机上不可辨认。
- 返工：只要修改文字内容、字体、字号、行距、文字框、构图比例或裁切，旧 typography receipt 立即失效。

## 适合跨流程统一的其他硬门禁

硬门禁只用于“可明确判定、漏检后果高、能够绑定到确切产物”的事项；主观偏好继续作为评分或人工选择，不能无限增加阻断项。

| 类别 | 统一阻断条件 | 主要证据／回执 |
|---|---|---|
| 事实与证据 | 数字、时间线、医学与保险表述无来源状态；未知被写成事实；标题超出证据 | claim ledger、事实卡、用户确认记录、来源哈希 |
| 隐私与授权 | 人脸归属未确认；声音、姓名、医院、二维码、编号或组合识别风险未处理；授权范围不匹配 | subject binding、隐私窗口 QA、授权记录、成品哈希 |
| 素材与权利 | 图片、字体、音乐、引用或 AI 生成素材的权利／披露状态不明 | rights manifest、素材来源和许可证记录 |
| 视觉可用性 | 字号、对比度、安全区、遮挡、溢出、截断、碰撞或静默裁切失败 | typography receipt、DOM／关键帧／碰撞 QA |
| 音频与字幕 | 句尾截断、口误残留、异常响度跳变；字幕不以最终音频为准；跨语言译文未经确认 | 最终音频哈希、ASR／字幕时间轴、译文确认、响度报告 |
| 技术完整性 | 分辨率、帧率、音画时长、完整解码或文件哈希不符合合同；输入来源漂移 | ffprobe／完整解码／checksum receipt |
| 内容承诺一致 | 标题、封面、开头和正文回答的不是同一个承诺；个案边界被泛化 | packaging review、opening payoff、证据引用 |
| 发布边界 | 机构审核、客户确认、AI／个案声明或人工发布边界缺失；工具试图自行发布 | approval receipts、manual-only publication handoff |

以下项目不设成全局硬门禁：是否“高级”、是否有流量、留白风格、AI 味强弱、卡片或纯文字的偏好、具体动效风格。它们可以成为诊断项、候选评分或人工选择；只有当它们进一步造成可测的低可读性、遮挡、事实误导或合规风险时，才由对应硬门禁阻断。
