真人短视频的封面不再从零手写多套 HTML，也不依赖把一个竖版封面硬裁成所有平台比例。正式链路为：

1. `lucas-personal-visual-system`：提供颜色、字体、人物使用、视觉密度和品牌边界；
2. `video-title-cover build`：先按内容与现有素材评估完整公式池，经硬门禁和加权评分选出最值得测试的 2—3 组标题封面假设，并绑定开头兑现和证据；
3. 封面素材计划：优先安排专门拍摄的封面照片；已有视频帧、操作者批准参考图引导的人物表情／姿势候选、脱敏证据图和纯排版都必须显式选择，不静默替代；
4. `safe_media_layout_plan.v1`：真人照片、视频帧和证据图进入渲染前完成安全布局、隐私与禁止静默裁切检查；
5. `video-remotion-skill run-covers`：把同一候选注册为多个 Remotion `<Still>` 构图，按平台比例分别重排和渲染；
6. 视觉 QA：按各平台实际信息流尺寸检查小图可读性，并检查文字溢出、模糊、人眼与人脸、主体遮挡、安全区和重复帧；
7. 人工选择：封面只是实验候选，不因渲染或技术 QA 通过而自动取得发布权限。

这条路线属于 `case-video-candidate` 中 `handoff-video-owner` 的封面子流程，不新增第六种自媒体 workflow，也不新建第二个渲染器或 FFmpeg 出口。

## 动态公式路由

`A／B／C` 只表示平台测试槽位或候选编号，不代表固定的“故事／证据／结构”，也不固定为旧版的“搜索型／好奇型／证据型”。每条内容先比较完整公式池，再选最匹配、最有点击潜力且能兑现的 2—3 个候选：

| 公式 | 适用内容 |
|---|---|
| 故事现场 `story_scene` | 有真实人物、事件瞬间或一句能进入故事的原声 |
| 创作者服务动作 `creator_service_action` | 重点是你具体做了什么，而不是抽象服务口号 |
| 客户证言 `customer_testimonial` | 客户原声本身能独立证明体验或价值 |
| 证据焦点 `evidence_focus` | 脱敏原件、记录、通知书或关键证据足够强 |
| 数字反差 `numeric_contrast` | 两个可核实数字之间存在明确认知落差 |
| 流程顺序 `process_sequence` | 观众最需要看懂节点、步骤或先后关系 |
| 选择决策 `option_decision` | 多个方案之间的选择与权衡是主要冲突 |
| 取舍对比 `tradeoff` | 两地、两院、两种支付或照护条件需要并列比较 |
| 服务边界 `service_boundary` | 重点是哪些属于协议内，哪些需另行约定 |
| 个人经验 `personal_experience` | 主体是客户或创作者的个体经历与感受 |
| 编辑隐喻 `editorial_metaphor` | 缺少强照片或证据，但可用克制视觉隐喻表达主题 |

所有候选先过五项硬门禁：事实准确、授权成立、隐私处理完成、医疗保险边界通过、开头与正文能够兑现。任一失败即淘汰，不得靠高分进入候选。

通过门禁后按 100 分权重排序：内容匹配 25、可用视觉素材强度 20、信息差 20、可信度 10、标题与封面互补 10、手机小图可读性 10、目标受众匹配 5。这里的目标受众先由选题层冻结：本账号优先包括高净值家庭、正在配置保险的人和既有保险客户；需要陪诊、医疗资料整理、就医协同或理赔协助的人可作为次要服务受众，但不是唯一获客人群。每条内容只能指定一个首要受众，最多一个次要受众。各分项按 0—5 评分；得分只用于本次候选排序，不是 CTR 预测。默认取前 3 名；合格的强候选只有 2 个时就测试 2 个，不为凑满三个而加入弱方案。视觉差异只在接近同分时作为破同分依据，不能反过来强制凑“故事／证据／结构”。

旧版 `title_cover_candidate_spec.v1` 的 `searchable／curiosity／evidence_led` 继续只读兼容历史计划；新任务默认使用 `title_cover_candidate_spec.v2` 的动态公式路由。

每个候选必须同时记录：发布标题、封面短文案、视觉焦点、受众承诺、点击理由、开头兑现段、证据引用、素材来源、门禁结果和评分。标题与封面文字必须互补；规范化后完全相同则合同校验失败。封面叠加文字最长 24 个字符。

### 手机小图可读性验收

小图只作为 QA 派生预览，不另建一套封面、不进入正式素材目录。按以下尺寸以 100% 比例显示，禁止放大后判断：

- 16:9：360×203；
- B站 4:3：320×240；
- 竖版 3:4：270×360；
- 竖屏首帧 9:16：270×480。

可以在电脑的模拟信息流页面中显示，再用手机远程查看对应屏幕，不要求传输预览文件。每个 profile 必须完成两项人工门：一秒扫视能理解点击理由，三秒内能准确读完封面短文案。同时检查数字字形无歧义、人物／证据／文字无碰撞、边缘与平台 UI 无截断、证据类型及焦点可辨认。普通文字对比度至少 4.5:1，大字和有意义图形至少 3:1。

失败后的返工顺序固定为：删次要信息 → 调整换行与层级 → 放大文字或证据 → 移动人物或改变视觉关系 → 必要时更换构图。不得为了容纳全部信息继续缩小字体。QA 回执记录 profile、检查尺寸、`one_second_glance`、`three_second_read`、`number_ambiguity`、`collision_or_crop` 和结论；失败时继续保持 `candidate_only`。

## 拍摄前必须完成的封面准备

封面不是最后才从视频里随便截一帧。脚本和开头基本稳定后、正式拍摄前，先完成标题封面候选计划，再生成封面专用拍摄清单：

- 先检查手机实际保存的照片和视频是否镜像，不以取景预览作为判断依据；
- 选择并记录统一人物方向，绑定源文件哈希；方向锁定后再进入裁切、重构图、人脸打码、动效、字幕、水印和封面提取；
- 人物居中、人物靠左留右侧文字、人物靠右留左侧文字各拍一组；
- 横版和竖版分别构图，不以同一照片强行适配；
- 每组保留正常表情、轻微疑问、严肃说明等与内容相符的少量变化；
- 眼睛、手势和关键道具避开各 profile 的文字安全区；
- 不把夸张惊讶脸、虚假医院场景或不相关道具当成默认封面语言；
- 证据主导型封面可不拍人物，但必须准备不可逆脱敏的证据裁切副本。

若没有专门拍摄素材，可以显式选择 `video_frame`、`evidence_visual` 或 `typography_only`；这属于降级决策，不能伪装成已经完成专用封面拍摄。

需要新表情或新姿势时，也可以选择 `generated_lucas_portrait`：只能使用操作者批准的非镜像人物参考图，不能只凭文字造人；成图先保持候选级，人工复核痣、发缝、方向、脸宽、下颌、年龄、眼神和整体第一印象，并标明生成视觉。客户、患者、家属和所谓真实医院／咨询现场不得生成。参考图上传到任何外部服务仍需单独授权。

## 深度调研后的决策规则

### 1. 不是所有封面都应该拍真人

先看本条视频靠什么建立点击后的信任：

| 内容核心 | 默认封面 | 原因 |
|---|---|---|
| 你的提醒、判断、陪同或沟通动作 | 真人主导 | 观众需要先识别讲述者和服务主体 |
| 金额、时间线、条款、理赔或原件差异 | 证据主导 | 证据比人物更能兑现承诺 |
| 你的动作与证据缺一不可 | 真人＋证据 | 人物负责“是谁做的”，证据负责“凭什么相信” |
| 无可用人物、证据不足以独立成图 | 纯排版 | 明确降级，避免用虚构视觉填空 |

因此，“录视频当天拍封面”是对真人主导型的默认要求，不是要求每条视频都摆拍。质子治疗系列主线01适合真人主导；主线04更适合证据主导。

### 2. 专用照片通常优于临时截帧，但不是绝对规则

YouTube 官方建议在视频拍摄时同步拍摄多张照片，以便上传时有多种封面选择。照片模式更容易获得清楚的眼神、稳定表情、较高分辨率和可控留白；从视频中截帧容易受到口型、眨眼、运动模糊、压缩和既有构图限制。这一技术差异是从照片与视频采集方式推导出的制作判断，不应误写成“专用照片一定带来更高流量”。

视频帧仍然适合两类情况：它准确记录了无法复拍的真实瞬间；或者拍摄已结束，现有帧已经清晰、自然并能安全适配构图。当前主线01属于第二类补救方案。

### 3. 同一拍摄日完成，但横竖版分别构图

拍摄日增加 5—10 分钟封面环节，最低拍摄组合为：

- 竖版人物靠左、靠右、近居中；
- 横版人物靠左、靠右；
- 每个构图拍平静说明、轻微疑问或与本条冲突匹配的两到三种自然表情；
- 有关键物件时，另拍看向、拿着或指向物件的画面；
- 每个构图至少保留三张清晰照片。

不要指望一张竖版照片同时承担 3:4、9:16、4:3 和 16:9。不同画幅共享服装、表情、道具和视觉承诺，但人物位置与留白应重新安排。

### 4. 保险和医疗内容不套用“夸张表情越好”的通用说法

YouTube 官方把表情和动作视为面向普通观众时可能有效的视觉线索，但同时要求标题和封面准确代表内容。对保险、疾病与客户经历，夸张惊恐脸容易把真实风险变成恐惧营销，也与“看事实、讲条件、给下一步”的个人品牌冲突。

本体系只允许与内容一致的自然表情：认真说明、轻微担忧、思考、疑问、确认和释然。禁止用张嘴震惊、夸张指脸、假医院、假白大褂或疾病恐惧图代替真实内容。

### 5. 测试差异假设，不测试细枝末节

YouTube 当前允许最多三组标题和封面同时测试，并按观看时长占比而不是单纯点击率判断。官方也提醒，过于相似的候选难以得出结果。因此候选之间应验证不同且与本条内容匹配的点击假设，而不是只换一个颜色、挪动一个字或稍微换表情；但差异化不能凌驾于内容匹配，不能强制每条都凑固定三类。

没有原生并行测试的平台，只记录发布入口、封面版本、内容类型和后续表现；不能把不同日期、不同流量来源的顺序替换冒充严格 A/B 测试。点击率提高但观看留存下降时，优先判断封面是否承诺过度。

### 6. 提示词结构与高密度候选

图片模型或提示词生成器统一按“身份与来源 → 人物位置／占比／表情／姿势 → 封面文字层级 → 素材角色 → 背景 → 装饰与视线引导 → 比例和安全区 → QA 与披露”装配。只吸收这一结构，不复制第三方固定配色、贴纸和话术。

高密度信息封面只作为动态候选：优先用于 `灿哥精进` 的 AI 教程、工具流程、产品测评和 3—5 项短清单；必须通过一秒理解、三秒读完的小图门。医疗、保险和客户案例默认仍由真人、证据或单一决策焦点主导。高密度风格不绑定 A／B／C，也不能通过缩小字体和堆叠英雄元素勉强通过。

## 平台证据与本地口径

- YouTube 长视频：官方目前建议 3840×2160、16:9；Shorts 建议 2160×3840、9:16。现有本地 `youtube_16_9` 与长视频一致；`vertical_first_frame_9_16` 是通用 1080×1920 首帧，不应误报成已经满足 YouTube Shorts 的最高推荐尺寸。
