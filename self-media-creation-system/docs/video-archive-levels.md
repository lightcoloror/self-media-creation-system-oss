# 视频项目归档分级

更新：2026-10-12 17:42:15 +08:00｜Codex（GPT-6；具体运行变体未独立核验）。按用户本次直接要求，今后默认做可返工归档，根据实际恢复需求决定是否升级为可复现归档。

## 默认与升级依据

先写一句“以后可能要改什么”，再选归档深度。默认 `rework`（可返工）；简单留存必须显式选择并写明理由。文件多、体积大、医疗题材或系列视频本身都不是升级依据。

以下需求成立时建议 `reproducible`（可复现）：跨机器或迁移目录后重新生成；长期封存后仍要重新生成；预期修改依赖复杂动效、打码或版本敏感处理；需要重放事实修正与证据相关处理；恢复失败成本很高，现有母版不足以覆盖预期修改。如果锁定母版已经覆盖实际修改需求，可以保留可返工级，但需说明理由。未知项保留 `null`，不能为了完成表格填写 `false`。

| 等级 | 用途与保留内容 | 验收范围 |
|---|---|---|
| 简单留存 `simple` | 明确只想回看：终稿、最终封面/文案/字幕、README、文件哈希清单、原片或已核验私有备份引用 | 清单与哈希、终稿可打开、原片备份引用可解析；不承诺返工 |
| **可返工 `rework`（默认）** | 上述内容，加已采用的精剪素材、可继续修改的关键母版、剪辑时间和来源映射、字幕/音量/动效配方、可取得的独立音轨/图层、人工修正与验收记录、复用素材引用、缺失项 | 按预期修改项逐项找到输入和操作入口；标清压平图层及做不到的修改 |
| 可复现 `reproducible` | 上述内容，加可执行入口、依赖版本、必要工具/字体/模型或经过核验的获取办法、相对路径或重绑定说明、限定范围的重建回执 | 在迁移后的独立目录实跑声明范围，不能暗用旧工作区或未登记缓存；比较画面、音频、字幕和关键语义，注明精确哈希一致或其他比较方法 |

“全量”指恢复目标所需的完整依赖，不是整个工作目录。依赖尚未理清而又将迁移/清理时，可以临时保存工作现场，并写明复查条件；现场快照本身不能证明可复现。

## 项目收尾操作

1. 锁定实际采用的版本与对应人审记录，复用当前生命周期清单和素材 ID。写明恢复目标，评估五项升级因素。未另行说明时按可返工收尾；只有明确只需回看时才考虑简单留存。
2. 复制 [评估模板](../templates/video-archive-assessment.json)，填入项目实际情况。调用原有生命周期 CLI：

   ```powershell
   # 工作目录：<workspace>/self-media-creation-system
   python scripts/artifact_lifecycle.py archive-policy
   python scripts/artifact_lifecycle.py archive-plan --assessment <项目评估.json> --output <新的归档计划.json>
   ```

   `archive-plan` 只写计划，不扫描真实媒体、不打包、不渲染，也不自动复制、上传或删除。已有输出拒绝覆盖。它输出所选等级、推荐依据、未评估因素、材料清单、待验收项与缺口；所有完成/上传/复现标记初始为 false。
3. 按计划整理材料，**素材与配方放在同一项目归档入口下**。建议保留“终稿、精剪与关键母版、原片或素材库引用、字幕与配方、依赖与复用素材、验收与清单”；目录名沿用项目已有布局，不另建重复层级。每条配方明确输入、输出、时间基准、步骤及覆盖的修改范围。已有原生工程就保存；JSON 请求包、配方和压平 MP4 不能冒充原生编辑工程。
4. 逐项检查。可返工至少能定位到预期修改所需材料；只有说明书或只有烧录成片，都不能据此声称任意返工。缺独立旁白、片头文字等时，写明“可修改哪些、哪些需要重做”。可复现只对实际执行过的阶段、环境和版本出具回执；终稿能探测、哈希一致和能从配方重建是不同证据。
5. 更新 README 与现有清单，分别记录：等级已选、材料已收集、完整性已验、指定范围重建已验、已上传、网盘下载回验。未执行的保留待验；用户说已上传可记录为用户确认，不能写成工具已远程核验。
6. 归档验收之后才进入已有 [生命周期与清理流程](自媒体产物生命周期与大视频清理流程-2026-08-28.md)。归档计划不授予删除、上传、发布或原片迁移权限，原清理保护和审批保持有效。

## 保留与省空间

- 不可替代原片、已采用的人工修正、最终采用版本与其验收、必要来源/权利/事实处理证据必须保住。可以用现有私有素材库中的稳定 ID、位置、哈希及已核验备份引用，避免每个项目重复复制原片；沿用所在工作区已有素材登记入口，不要求安装另一套素材库。归档级别不决定原片可否删除。
- 默认不收入可重建的 ASR 分块、重复识别、帧缓存、浏览器资料/凭据、废弃全长渲染、未采用封面和通用运行缓存；“不收入新归档”不等于“现在删除源文件”。仍有诊断或独立价值的例外记录理由。
- 保留能覆盖修改目标的关键母版即可，不保存所有中间版本。下载链接若易失效、依赖版本敏感或要求离线恢复，应保留必要的实际依赖文件；不能用一个未验证链接替代依赖齐备。
- 新增渲染、搬运大文件前仍做资源和磁盘检查。不可因升级归档而默认重新跑模型、GPU 或全片渲染。
