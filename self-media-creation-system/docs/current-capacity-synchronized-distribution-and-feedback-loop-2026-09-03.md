# 当前容量下的同步分发与五平台反馈闭环

- 状态：current operating decision
- Acting tool/model：Codex (GPT-5.6 Sol)
- 更新时间：2026-09-03 18:49:02
- 边界：人工发布；本地导入；不登录平台；不把账号日数据归因到单条内容

## 当前经营决策

当前只有能力完成一个母稿、一个成片，再人工同步分发到多个平台。因此正式采用：

`single-master-synchronized` → `same-frozen-master-manual-multi-platform`

这不是平台最佳形态，而是当前资源约束下的合理模式。以下两项延期，不阻断创作或发布：

- 同一母稿派生快节奏版、信任叙事版、搜索图文版；
- 标题、封面或开场的单变量实验。

以后只有在稳定完成发布、数据回填与复盘仍有余力时，才启用平台变体或单变量实验。延期期间不伪称正在做实验，也不因没有实验而阻断发布。

## 已进入创作门禁的新增要求

短视频故事卡现在必须声明一套可检验的时间结构：

- 0–2 秒：观众能看见具体处境、异常结果或与自己的关系；
- 2–5 秒：给出继续看的理由；
- 5–15 秒：出现第一个动作、数字、选择、证据或结果；
- 其后最大信息停滞区间使用 8–15 秒的工作假设；
- 第一个有意义的回报不得拖到最后 20% 才出现。

这些数字是当前运营假设，不是平台算法事实。每条仍需独立成立，不能依赖“上一集”或“下一集”才能理解。

故事卡同时增加持续价值字段：

`本条解决什么 + 以后持续解决什么 + 写给谁`

它不是机械的“关注我”，也不要求每条都口播出来；可以体现在字幕、说明文字或账号长期一致性中。如果本条不展示，会保留提醒但不自动阻断。

## 发布前冻结

同步分发前生成 `publication-version-freeze.v1`，只保存：

- 实际标题；
- 封面文字和视觉描述；
- 实际前一至两句及其哈希；
- 正文哈希；
- 视频总时长和文件 SHA-256；总时长优先直接读取最终发布文件，不要求平台导出提供；
- 本次同步分发的平台列表。

不复制封面图片或视频。冻结对象不能授予发布、外发或执行权限；真实发布仍由人完成。已有 publication event 可通过自己的 `cover_refs` / `media_refs` 指向该冻结清单，旧事件合同无需破坏性升级。

## 五个平台的数据字典与导入边界

权威映射为 `config/platform-metric-mappings.v1.json`，本地导入器为 `scripts/platform_metrics_intake.py`。一个平台可以同时有作品级和账号日级导出，因此导入键使用 `export_profile`，不再假定“一个平台只能对应一种导出表”。

本轮五个平台、七份导出已生成 58 条离线记录：`.runtime/platform-metrics-intake/five-platforms-20260903/intake.json`。其中抖音和快手同时保留作品级与账号日级导出；前者用于单条内容分析，后者只用于账号时间窗口。该运行产物留在本地，不作为通用代码提交内容。内容信号字典已升级为 `cold-start-content-signals.1.1`。

| 平台 | 原始粒度 | 可否直接归到单条内容 | 关键口径 |
| --- | --- | --- | --- |
| 小红书 | 单条笔记 | 可以 | 曝光、观看、封面点击率、互动、笔记涨粉、人均观看时长 |
| 微信视频号 | 单条视频 | 可以 | 播放、完播、平均播放时长、推荐、互动、关注、私域转发 |
| B站 | 单条稿件 | 可以 | 播放、3秒跳出、互动、涨粉、取关、平均播放进度；点击率“星级”不冒充百分比 |
| 抖音 | 单条作品＋账号×自然日 | 作品表可以；账号日表不可以 | 作品表含播放、完播、5秒留存、2秒跳出、平均时长、互动、主页访问与单条涨粉；账号日表只描述日期窗口 |

`net_follower_change` 是可正可负的账号净变化；`attributed_new_followers` 是平台明确归到单条内容的涨粉。两者不得互换。无数据、平台未提供和真实的零也不得混为一类。

视频时长采用独立的媒体证据优先级：`最终发布文件实测 > 已绑定该文件的发布清单 > 平台导出时长 > unknown`。`publication_version_freeze.py probe-media` 或 `create --media-file` 会读取最终文件的 SHA-256 与 ffprobe 时长，但不会复制视频，也不会把绝对路径写入冻结对象。

## 本轮五份真实导出的可支持判断

数据范围只有 2026-08-26 至 2026-09-02 左右的首轮小样本，不能据此宣称平台算法规律。

1. 小红书的“他没把复查当回事……”获得 732 曝光、166 观看、6.5% 封面点击率和 20 秒人均观看，明显好于该平台其余三条的入口表现；20 秒约占 96.521 秒成片的 20.72%。抖音同题人均观看 9.74 秒、完播率 2.92%，也是四条中最高，并带来 1 个单条归因涨粉。说明“人物行为 + 你的具体动作”值得继续验证。
2. “确诊后，我把3件事放在一起查”在小红书只有 5 秒人均观看，约占 90.911 秒成片的 5.50%；B站同题显示 58.3% 的 3 秒跳出和 7.1% 平均播放进度；抖音同题 5 秒留存 29.70%、2 秒跳出 34.65%，均是本轮四条中较弱的一端。三个作品级来源共同支持优先检查开场兑现和第一个信息推进，而不是先升级画面。
3. “一次拿不出近30万……”在小红书只有 37 曝光、5 观看和 0% 封面点击率，但进入后的 5 人平均观看 23 秒，约占 126.210 秒成片的 18.22%；视频号同题平均播放 33.57 秒，约占成片的 26.60%，播放 403、完播率 2.24%。抖音同题播放 313，为本轮四条最高，但平均播放仅 6.96 秒、完播率 0.32%。入口分发和看进去后的消费必须分开判断。
4. 视频号“确诊后……”在三条中播放最高（566）、完播率最高（4.42%），且出现 2 次分享和 2 次私域转发。它在小红书/B站的消费表现却弱，证明同片同步分发可以节省产能，但平台结果不能直接等同。
5. 抖音作品表已经可以逐条归因。四条中“两位医生都建议手术……”的 5 秒留存最高（45.74%）、2 秒跳出最低（22.34%），但播放只有 99；“一次拿不出近30万……”播放最高（313），消费指标却较弱。样本进一步说明曝光、首段留存和完整消费不是同一个问题。账号日表继续保留，但不再承担单条归因。
6. 快手作品表也已经可以逐条归因：四条播放依次为 3,019、1,183、3,066、3,062；“确诊后……”获得 1 个单条归因涨粉。作品级完播率均为 `--`，因此可以比较播放和互动，不能据此比较完播。账号日表只用于时间趋势，不能覆盖作品表的单条结论。
7. B站只有 91 次总播放，且存在“5 播放、5 评论”的异常小样本。暂不据此判断选题或结构优劣。

## 调整后的最小闭环

```text
经营目标：涨粉 / 信任 / 收藏
→ 选题与证据
→ 选择目标受众和同步分发平台
→ 设计 0–2 / 2–5 / 5–15 秒与后续信息推进
→ 故事、情绪和单条独立成立检查
→ 写明本条价值、长期价值和目标观众
→ 标题 / 封面 / 开场一致性检查
→ 冻结真实标题、封面描述、前两句、时长和媒体哈希
→ 人工同步发布同一成片
→ 导入五个平台的作品级数据；账号日级数据作为补充
→ 保留 export profile、平台粒度、缺失值与不可比说明
→ 同平台、相近时长、相同形式比较
→ 在下一条只优先修最明显的瓶颈；暂不宣称单变量实验
```

## 变更理由与回滚

- 意图：让创作门禁直接覆盖首秒留存、提前回报、持续关注理由、精确发布版本和五平台真实数据。
- 决策：当前只维护一个同步分发母版；高成本平台变体和实验延期。
- 理由：现有数据的最大缺口是发布时间结构、时长、发布版本与平台粒度，而不是缺更多文案模板。
- 证据：五个平台的七份用户提供导出、四个最终发布文件实测，以及现有故事卡、反馈跟踪合同的代码审计。
- 生效范围：故事结构设计、发布前冻结、本地数据导入与反馈指标；不改变人工发布边界。
- 回滚：删除新增的映射、导入器和冻结合同；回退故事卡新增字段及 `publication_feedback_tracker.py` 的指标扩展。既有 publication event 和 performance snapshot 保持兼容。
