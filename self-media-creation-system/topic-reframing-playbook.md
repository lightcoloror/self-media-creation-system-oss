# 问答选题分流与条件式重构操作卡

> 状态：v1.1 人工执行卡
> 更新时间：2026-08-13 23:45:18
> 执行者：Codex（GPT-5.6 Sol）
> 适用范围：真实问题问答、搜索型选题和误区澄清；不适用于所有选题

本卡只负责判断“原问题是否需要重构”。正文怎样展开，另按 [内容结构路线库与人工改道规则](./structure-route-playbook.md) 选择 `structure_route`；两层不要合并成一个强制模板。

## 先判断题材，不先套结构

“流量入口—真正问题—客户决策”只是问答选题中的一种路线，不是全系统的固定结构。

先选择：

```yaml
question_structure_route: direct-answer | decision-reframe | not-applicable
```

### `direct-answer`：问题本身已经准确

直接回答用户提出的问题。可以补条件、证据和边界，但不要为了显得专业而另造一个“真正问题”。

适合：

- 一个术语是什么意思；
- 某项责任是否写进合同；
- 理赔需要准备哪些材料；
- 某个流程怎样办理；
- 一个明确场景下有哪些选择。

最小结构可以是：

```text
直接答案 → 必要条件/证据 → 适用边界或下一步
```

### `decision-reframe`：表面问法遮住了真正决定

只有发现原问题混淆对象、遗漏关键前提、把产品当答案，或者简单“是/否”会误导时，才使用这条路线。

```text
保留普通人的问法作为入口
→ 先给表面问题一个短答案
→ 只向前重构一层
→ 帮助读者完成一个现实决定
```

适合：

- “有医保，还需要百万医疗险吗？”
- “重疾险和百万医疗险只能选一个吗？”
- “体检异常后还能买医疗险吗？”（当真正问题是异常怎样改变投保路径时）

使用条件：必须能明确写出原问遗漏了什么，以及重构后怎样改变客户行动。写不出来就回到 `direct-answer`。

### `not-applicable`：不是问答型题材

案例复盘、个人故事、服务过程、工具教程、观点表达、机制解释、访谈等继续使用各自的内容结构，不填写问题重构卡。

## 只有 `decision-reframe` 才填写

```yaml
audience_entry_question: 普通人实际会问、会搜的原问题
surface_answer: 对原问题的一句话条件式回答
hidden_assumptions: []
professional_core_question: 真正需要回答的问题
client_decision: 读者最终要决定或完成什么动作
public_value_bridge:
  misconception: 只纠正一个关键误区
  distinction: 只拆开一个关键区别
  action: 只给一个立即可做的动作
scope_boundary: 哪些特殊人群或后续问题不在本篇展开
backstage_research_refs: []
```

`direct-answer` 只需记录原问题、直接答案和必要边界，不强制制造 `professional_core_question` 或 `client_decision`。

## 专业度是受众校准，不是统一结构

“后台研究足够严谨，前台表达让目标受众能理解和使用”适用于整个系统；但不同题材呈现专业性的方式不同：

| 题材 | 专业性主要体现 |
|---|---|
| 直接问答 | 回答准确、条件完整、边界清楚 |
| 决策重构 | 发现原问遗漏的关键前提，并给出判断方法 |
| 案例复盘 | 服务动作、判断节点和结果边界真实 |
| 工具/清单 | 步骤可执行，失败条件和适用范围清楚 |
| 机制解释 | 因果链清楚，证据与推断分开 |
| 个人故事 | 处境、选择和感受真实，不硬塞知识点 |
| 观点内容 | 立场、依据、反例和代价说清楚 |

因此，“一个误区＋一个区别＋一个行动”只用于 `decision-reframe`，不检查其他题材。

## 失败模式

2026-10-09 18:50:58 +08:00｜Codex（GPT-6）：评论原问与推测的深层任务必须分开保留。例如“这支笔哪里买”可以先直接答；“想学整套拍摄方法”仅为待验证假设，不能替用户宣布目的。通过已授权的脱敏反馈或实际追问验证后再决定是否扩成系列。观点稿的反例检验在现有提纲给出“原判断→反例→收窄后判断／有依据保留”，不新增所有稿件的必过理论门。

- 所有搜索题都先宣布“你问错了”。
- 问题本来可以直接回答，却硬造一个更宏大的核心问题。
- 案例、故事和工具内容被改造成同一种决策清单。
- 标题问 A，正文借重构之名讲或卖 B。
- 连续重构多层，把客户带进同行课程。
- 为了通俗，隐藏会改变答案的重要限制。

## 发布前检查

所有内容先检查：

- [ ] 已按题材选择结构，而不是套用统一模板。
- [ ] 专业度与目标受众、内容任务和平台场景匹配。
- [ ] 没有为了显示专业而增加无助于本篇目标的复杂度。

仅 `direct-answer`：

- [ ] 已直接回答原问题，条件与边界足够。
- [ ] 没有无必要地把问题改写成另一个问题。

仅 `decision-reframe`：

- [ ] 原问确实存在会影响决定的遗漏或混淆。
- [ ] 重构前已经短答原问题，没有答非所问。
- [ ] 只重构一层，只解决一个客户决定。
- [ ] 只纠正一个误区、拆开一个关键区别、给一个行动。

## 当前保险案例

```yaml
question_structure_route: decision-reframe
audience_entry_question: 有医保，还需要百万医疗险吗？
surface_answer: 不一定，要看已有保障后的缺口以及商业医疗险能否补上。
hidden_assumptions:
  - 把有医保等同于保障充分
  - 把百万医疗险等同于商业医疗险的唯一答案
professional_core_question: 普通医保报销后，是否仍有家庭承担不起、且商业医疗险能够补上的费用？
client_decision: 需要补、可以暂缓，还是目标保险补错了地方
scope_boundary: 公费医疗和具体产品选品另篇讨论
```

## 内容框架决定：在结构、故事和正式包装之前

更新：2026-10-10T09:28:29+08:00；Codex（GPT-6）。本节补齐框架决策，不把诊断通过当成优化完成。

“框架”是同一份素材被讲成什么问题、向谁承诺什么价值，以及它与本篇目标、账号方向和实际承接的关系。它先于“用故事、问答还是比较展开”。课程 29:23—31:11、33:28—36:00 提供这一思路；下述四种结果与版本检查是本项目的落地设计，不冒充课程原有表单、学术定义或流量定律。

先复用已知任务信息，记录可改范围：正文能否改、能否重写、能否补录、只能剪已有素材还是只能改包装。已有明确方向的局部修改不重开全套探索；复用决定须核对目标、受众、核心承诺、事实材料和可改范围仍然相同。任何一项实质改变，都重新判断。

每个候选框架分别交代：

| 项目 | 必须说清楚的内容 |
|---|---|
| 问题与承诺 | 这篇究竟让观众理解或解决什么；正文哪里兑现 |
| 受众与所得 | 谁会进来；与原受众相比扩大、缩窄或转移到谁；他们得到什么 |
| 目标与承接 | 单条主要目标；已知产品/服务、适用对象及这类观众与购买者的关系；未知就记未知；信任/表达内容可记“本篇不以转化为目标” |
| 证据与素材 | 哪些事实支撑承诺；缺什么；对标只支持表达取舍还是有可比成效证据 |
| 成本与可行性 | 具体要改哪些段落、补哪些材料/镜头、预计投入依据；没有实测就不填伪精确时长 |
| 取舍理由 | 为什么选或不选；扩大受众是否稀释目标；不是用高/中/低或“可能会爆”替代理由 |

### 四种结果与下一步

| 结果 | 适用条件 | 具体交付 | 下游状态 |
|---|---|---|---|
| 继续 `continue` | 当前框架匹配目标、承诺有材料支撑、投入值得 | 保留主线或局部修改的理由、选中方向、当前材料版本、作者决定 | 完成现有人工方向确认后进入结构、故事、初稿；仍须后续事实、口吻、包装等审核 |
| 重构 `reframe` | 素材值得保留，但问题、受众或核心承诺选错 | 退回框架比较；说明局部改还是整稿重写、旧段落如何处理 | 不进入正式包装/制作；先写出新稿和前后差异，再重新判断，不能只改标题 |
| 补材料 `supplement` | 方向有价值，但证据、经历细节或镜头不够 | 缺口清单、取得方式、授权/可改范围、恢复条件 | 只进入所需研究或素材准备；补齐后生成新决定，不能拿旧“补材料”决定去写稿放行 |
| 暂缓 `defer` | 当前目标下不值得投入，或在允许范围内无法兑现 | 具体原因、保留素材及可再利用用途、重新打开的条件 | 当前篇暂停制作/发布；不删除原稿，不凭AI猜测“不会爆”自动弃稿 |

允许所有候选都不选。已拍完不能补录时，也可以缩小承诺、重剪现有材料或暂缓，但不得伪造新经历/同期声。重构不是必须整稿重写：只有旧主线依赖被否定的框架时才整稿重写；改动越小也必须实际落稿。

### 接入现有入口

继续使用 `scripts/topic_angle_decision.py`，当前输入/结果为 `topic-angle-decision-input.v2` / `topic-angle-decision.v2`。v1历史结果可读取，但不能证明做过框架判断。v2绑定当前素材文件与证据哈希，逐一比较候选；重构/暂缓的 `selected_angle_id` 可以且必须为空。

```text
python scripts/topic_angle_decision.py create --input <input.v2.json> --output <.runtime/decision.json>
python scripts/topic_angle_decision.py next-step --receipt <.runtime/decision.json> --stage draft
```

`next-step` 只返回编辑路线，不执行写作、采集或发布。待人工确认、重构、补材料、暂缓均不能通往写稿；已确认的补材料决定可在 `--stage research` 返回研究路线。`prepare-step` 与已生成handoff的重新核验都会在适用写稿步骤消费这一决定，防止只把回执当附件；图文研究完成后还要重新提交 `continue` 决定。原五种任务入口保留，案例路线仅在适用上游选题决定时消费此扩展，纯技术返工不强加重新选题。

程序只能检查字段、版本、已声明结果和路径约束，不能证明AI对受众的推断正确、人工实际同意、改稿已经有效或真实商业转化成立。人工确认仍按现有人工门执行，不由Agent自行填写通过。

### Skill职责与两次检查

- `dbs-content-value`：诊断谁会看、得到什么、正文是否支持、与已知产品/服务的关系；不代替事实核验和实际改稿。
- `dbs-title-cover-intro`：统一调度框架探索与标题/封面文字/开头。写前可作标明状态的联合探索；正文稳定并经过适用确认后，才做正式包装。方向未定时按该Skill的完整探索要求执行；已锁定方向的局部修改走其短路规则，不重复开角度团队。
- `title-matrix`：需要跨平台比较、标题诊断或复盘时复用；只保留一条角度流程和一条标题流程，不与协调Skill重复生成。
- `dbs-hook`、`dbs-xhs-title`：历史兼容入口；新任务默认使用 `dbs-title-cover-intro`，明确指定旧版时才按用户要求比较。

写前先判值不值得写；初稿审核再次逐项对照实际段落。框架失败退回这一层，不交给口吻润色救场。改稿后要有“旧句/旧结构→新句/新结构→理由与证据→复核结果”，或有证据的保留决定。检查、修改、作者确认、真实观众效果分别记录。
