# 自媒体创作全链路 Token 节省操作卡

> 状态：第一阶段已实现
> 更新时间：2026-08-22
> 执行者：Codex（GPT-5.6 Sol）
> 边界：减少重复上下文、无界输出和无效重跑；不删除事实、用户修正、授权、隐私、医疗保险合规或人工发布门。

## 结论

Token 优化不等于把提示词写短，也不等于少做审核。最有效的办法是：只让模型看到当前决策需要的上下文，把完整材料、搜索命中和运行日志留在磁盘，通过路径、哈希和短回执引用；发生冲突或失败时再按需读取。

第一阶段统一入口：

```powershell
python scripts/context_efficiency.py search --root <root> --query <text> --output <search.json>
python scripts/context_efficiency.py pack --manifest <context-input.json> --output <context-receipt.json>
python scripts/context_efficiency.py summarize-log --log <full.log> --output <log-summary.json>
python scripts/context_efficiency.py decide-asr --audio <audio.wav> --previous-receipt <previous.json> --output <decision.json>
python scripts/context_efficiency.py plan-video-review --manifest <video-review-input.json> --output <video-review-plan.json>
python scripts/context_efficiency.py verify-video-review --plan <video-review-plan.json> --receipt <executor-receipt.json> --output <verification.json>
```

## 各环节的默认优化

| 环节 | 默认只加载 | 留在磁盘、按需读取 | 不得省略 |
|---|---|---|---|
| 选题 | 受众、首要目标、高频问题计数、候选前 3 | 全部历史选题、完整评论池 | 真实问题证据、账号/IP、合规边界 |
| 搜索发现 | 查询式、来源范围、命中摘要 | 完整命中 JSON | 查询边界、截断状态、来源路径 |
| 深度研究 | 当前 claim、相关 evidence/source/unknown/contradiction | 无关章节、旧抓取日志、已否决候选 | 来源状态、哈希、时间、矛盾和未知项 |
| 写作 | 路由卡、事实卡、本人声纹短核、当前草稿 | 全量写作教程、历史所有版本 | 用户修正、事实、隐私与禁用表达 |
| 标题/封面 | 正文稳定稿、唯一承诺、平台适配 | 全文研究包、所有标题历史 | 标题与正文一致；正文变化使包装失效 |
| 图文/视觉 | 页面任务、视觉角色、可用素材清单 | 原始图库、完整渲染日志 | 版权、来源、隐私、安全区、移动端可读性 |
| 视频脚本 | 稳定正文、场景映射、证据引用 | 完整访谈史、旧脚本诊断 | 原声授权、事实边界、人工口吻确认 |
| 剪辑/渲染 | 编辑决策单、变更窗口、验收帧 | 完整历史日志、冻结窗口素材 | 基础视频和素材哈希、隐私遮罩、音频状态 |
| 返工 | 失败项、变更窗口、依赖失效门 | 已通过窗口和整套旧报告 | 冻结范围、差异证明、下游重验 |
| 发布/反馈 | 冻结版本、人工发布回执、观察窗口 | 无关创作过程 | manual-only、内容/业务信号分层、no_signal 中性 |

## 机器规则

### 有界搜索

- 默认排除 `.git`、`node_modules`、缓存、构建目录、`outputs`、`logs` 和临时目录。
- 默认只搜索文本扩展名，单文件不超过 2 MB。
- 命中上限后返回 `refine_query_required`，不能把截断结果冒充完整结果。
- 完整命中写入 JSON；对话只返回数量、路径、哈希和最多 5 条预览。

### 上下文装载清单

- 每一轮明确 `inline`、`reference`、`on_failure`。
- 相同 SHA-256 的文件只计一次，避免相同内容以多个文件名反复进入上下文。
- `fact_baseline`、`approved_script`、`user_correction`、`privacy_authorization`、`medical_insurance_boundary`、`source_manifest` 必须带预期哈希，且不能降为 `on_failure`。
- 超过内联预算时 fail-closed，由人或 Agent 调整装载方案；不自动截断事实。

### 日志与 ASR

- 完整日志始终留在磁盘；正常只回传状态、路径、SHA-256、大小和错误附近有限行。
- 只有音频 SHA-256 完全不变时才复用 ASR。
- 音频变化且明确变更窗口时，可仅重跑该窗口并保留前后 2 秒上下文；边界不明确则重跑完整 ASR。

### 代理审片、关键帧与变更窗口

- 首轮审片只生成 540×960、900 kbps、烧录时间码的低码率代理计划，用于确认内容、剪切、版式和隐私；它不是最终候选。
- 计划必须绑定源视频、编辑决策单和现有 `video_creation_pipeline.rough_cut_workspace.v2` 的路径与 SHA-256。
- 实际执行 Owner 固定为 `mvp-video-pipeline`，渲染固定通过 `video_creation_pipeline.single_ffmpeg_outlet`；本仓不实现第二套 FFmpeg 编排。
- 首轮计划覆盖完整时间线；局部返工计划只包含声明的变更窗口，并明确冻结窗口。变更窗口与冻结窗口不得重叠。
- 每轮必须指定 3–5 个验收帧。局部返工的验收帧必须位于变更窗口内，避免重新审阅已经冻结的全片。
- 音频、时间、视觉源、遮罩、字幕、速度和重压缩分别触发确定性的下游失效门；例如只改字幕不会无条件重跑 ASR。
- 执行回执必须绑定代理片、验收帧、完整日志、Owner 与 FFmpeg 出口；完整日志仍留盘，不进入回执正文。
- `pass` 必须同时通过完整解码、关键帧、隐私候选、正常速度人工审片。通过后只表示允许生成最终候选；最终解码、响度、字幕、隐私和移动端可读性仍须按失效图重跑。
- 执行回执永远不得声称已生成最终候选或自动发布。

### 人工审核精确范围门

- 不允许只说“请检查这条视频”或“看一下大约 46 秒”。每个人工审核项必须写明候选文件及 SHA-256、问题起止秒、实际观看起止秒、`MM:SS.mmm`、审核类别、播放方式和唯一判断问题。
- 已定位问题默认取问题前 2 秒、后 3 秒作为上下文；观看窗口超过 15 秒时拆成多个独立时间范围。
- 默认只给原候选路径、哈希和精确时间范围，不生成独立审片文件。只有用户明确要求、原文件无法可靠跳转、远程审核者无法访问原件或确实需要盲审时，才生成 `human_review_clips`。
- 人工只需对每个 `human_review_requests.review_id` 返回 `pass`、`needs_rework` 或 `uncertain`。
- 只有全部局部问题关闭后的最终观众审看可以使用整条视频；仍须给出精确的 `00:00.000–结束时间`、总时长与候选哈希。
- 候选哈希变化、时间范围越界或审核结果未逐项绑定时，回执 fail-closed，不得要求人工凭记忆寻找问题；只有显式要求独立审片时，审片缺失才构成失败。

### VKP 统一人工审核界面

- 音频、字幕、画面/动效、隐私、合规、发布观感及混合问题，只要需要对视频时间轴作人工判断，统一投影到 VKP `targeted-review`，不在聊天、剪辑仓或自媒体仓另建播放器。
- 一个审核包可以引用多条原视频；VKP 按 `source_id` 切换素材，按精确起止时间跳转并在区间终点自动暂停。默认不复制视频、不生成逐问题审片文件。
- 播放方式由问题决定：音频使用 `audio_only`，纯画面使用 `muted`，单帧隐私残留使用 `frame_step`，字幕、合规、发布和混合问题按需使用 `normal`。
- 人工只处理 Agent 和本地工具预筛后的少量区间，并在同一界面返回 `pass`、`needs_rework` 或 `uncertain`。完整日志、自动检测明细和源文件继续留在磁盘。
- 只有最终发布观感允许整条播放；其余已定位区间原则上不超过 15 秒。上游事实、脚本和来源审查仍走文本审查；不得把没有时间轴的文字问题硬塞入播放器。

## 质量不回退门

以下内容不进入节省范围：事实与来源、用户纠正后的原话、授权和隐私、医疗保险与广告边界、正文与标题承诺一致、正常速度试听、最终解码和响度、关键帧/移动端可读性、人工发布。

### 2026-08-28 16:40:22 +08:00

- 意图：让不同 Agent 真正命中同一份审核缓存，不因路径或合同格式漂移重复读取和解码媒体。
- 决策：`execute-review` 默认使用统一的本地托管缓存；媒体哈希与检查配置哈希规范化为一个 64 位缓存键；FFmpeg 回执复用已计算的媒体哈希，避免为写回执重复读取大文件。
