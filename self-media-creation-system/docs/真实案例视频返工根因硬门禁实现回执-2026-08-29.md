## 1. 段落级事实引用与时间顺序

- 意图：避免脚本在反复改写中把人物、动作、时间先后和因果关系改错，同时不要求细化到逐句引用。
- 决策：真实案例的非 CTA 段落必须提供 `fact_refs`；流程型案例默认使用 `chronological`。确需非时间顺序叙事时，必须选择 `editorial_nonchronological` 并写明理由。
- 理由：段落级引用足以约束叙事事实，又不会把口播写作变成逐句标注工作；时间顺序作为默认值可以阻止无意中的节点倒置。
- 证据：Content Studio 聚焦回归 `27 passed, 40 subtests passed`；新增缺少段落引用、时间倒序和非时间顺序缺理由三个负例。
- 生效范围：`content-route-card.v0`、`case-video-script.v1` 及真实案例脚本适配器。合成演示稿保持兼容。

## 2. 动效先作用于独立片段，再拼接终稿

- 意图：避免在已经拼接好的主片上添加证据动效，导致证据画面跨入客户采访段、遮住采访画面或压住采访声音对应内容。
- 决策：语义动效计划必须声明 `render_motion_segment_then_concat_master`；禁止终稿级覆盖；客户采访锚点禁止绑定语义动效。
- 理由：动效的作用域应由语义片段边界决定，而不是依赖终稿时间轴上的人工估算。
- 证据：MVP Video 相关回归 `31 passed, 2 skipped`；新增客户采访动效拒绝与终稿覆盖策略拒绝两个负例。
- 生效范围：MVP Video 的语义动效计划、构建器及后续 case-video handoff。

## 3. 人工确认人物归属与逐帧打码覆盖绑定

- 意图：避免“程序检测到很多脸，但打错采访者、漏掉受访者或在边界漏一帧”。
- 决策：人物归属由人工确认；程序只使用匿名轨迹编号。发布候选必须把人工确认的受访者、可见时间窗、匿名轨迹、打码区域和候选视频哈希绑定，并验证时间窗内每一帧都有覆盖。
- 理由：检测和追踪可以自动化，但“这张脸是谁”不能由检测器自行决定；逐帧覆盖才能把边界漏帧从抽检问题变成确定性失败。
- 证据：新增正例与单帧遗漏负例均通过；自媒体系统全套 `272 passed, 1 skipped, 51 subtests passed`，总合同检查另运行 `273 tests` 与 `38 tests`，全部通过。
- 生效范围：真实案例中需要马赛克的候选视频，在客户审看之前强制执行；不授予身份推断、上传或发布权限。

## 4. 生产任务冻结工具与规则版本

- 意图：避免同一视频一边制作、一边修改脚本、动效、字幕或隐私工具，造成不同片段由不同规则和代码版本生成。
- 决策：每个真实 case-video 任务在执行前创建 production-run lock，固定工具入口、规则文件、字节数与 SHA-256；任一固定文件变化都使下游候选失效，并要求新建一次生产运行。
- 理由：把工具研发与视频生产分开，才能判断返工究竟来自素材、配方还是代码漂移。
- 证据：新增稳定创建／验证正例，以及工具文件改变后返回 `production_toolchain_drift` 的负例；工具入口已加入 manifest 和 Agent discovery。
- 生效范围：真实 case-video production run。仍为本地 candidate-only，不授予上传或发布权限。

## 5. 路由与可发现性

- 意图：避免规则虽然写进代码，但后续 Agent 找不到入口或绕过门禁。
- 决策：case-video recipe 增加生产锁验证和隐私绑定验证两个独立步骤；任务胶囊最多 12 步、预算仍有限制并调整为 10 KiB；manifest 增加 create／verify／privacy binding 三个 CLI 入口。
- 理由：新增门禁必须有独立回执和确定顺序，不能只藏在长说明文字里。10 KiB 是当前实测 9,652 字节之上的有限预算，并未取消上下文上限。
- 证据：五条合成工作流、doctor、step handoff、缺失输入、哈希漂移和人工发布边界均通过回归。
- 生效范围：self-media Agent 的 case-video 路由；其他四条工作流不增加无关步骤。
