# 旅行／体验 Vlog：从出行准备到发布候选

更新：2026-10-10 13:20:00（Asia/Shanghai）｜Codex（GPT-6）；历史记录见文末。

入口与审核规则更新：2026-10-25 21:34:37 +08:00｜Codex（GPT-6）。入口不明确时先用[任务选择](workflow-entry-selection.md)恢复当前交付；本指南是选中体验／Vlog 后的创作分支。粗剪、精剪配方与素材审核都直接跳转原片时间区间，不导出审核片。只有用户明确要求实际成片或独立片段时才进入剪辑导出。

适用：个人创作者计划拍摄或已经拍摄的旅行、户外和体验素材。这是与 `story` 平行的 `travel-experience` 创作路由；先执行[每次创作路由判断](creation-route-selection.md)，返回本次主形态和理由。素材分析由 VKP 管，剪辑／渲染由现有 NLE 或 MVP Video 管，平台交付走现有人工发布门。五个固定 `workflow_goal` 不替代本路线，也不借用 `case_video_candidate` 冒充 Vlog。已拍完的项目从现有素材开始，不倒填出行前计划。

## 流程与交接

```text
本次 AI 路由判断（用户目标、素材依据、约束、主路由与形态）
→ 任务卡（账号、受众、目标、画幅／平台）
→ 出行前拍摄卡（观看任务、必要覆盖、不可补拍时刻、权利／隐私；仅计划拍摄时）
→ 现场真实拍摄与离场防漏检查
→ 原件双备份、来源／权利清单
→ VKP 多素材候选证据与事件计划
→ 镜头与声音日志、selects 和所选形态的声画分段方案
→ 纸面 EDL／分单元原片时间区间审核
→ 粗剪与精剪配方、原片叠加预览
→ 锁定声画、字幕、封面和平台版本
→ 自动技术检查＋人工完整观看／精确区间审核
→ 平台上传页人工确认
```

计划出行时先用[出行前拍摄卡](../templates/travel-experience-vlog-pre-shoot-card.md)防漏；回家后每一步用[工作单模板](../templates/travel-experience-vlog-work-sheet.md)记录输入、来源时间码、判断与未决项。拍摄卡只写问题和可能需要的镜头，不预写结果或摆拍真实事件。原件始终只读；代理文件、候选配方、转写、标签和评分不替代人工看听。

VKP 入口在 `<workspace>\video-knowledge-pipeline` 下。先读 `personal-vlog-doctor` 的可用性与降级项；原件已备份、项目输出目录已确定且本地 ASR 资源可用后，才能按以下顺序启动。`run` 会分析有效视频并写入项目派生目录，可能耗时和占用磁盘；不执行渲染或发布。

```text
personal-vlog-doctor
personal-vlog-prepare <只读活动素材目录> --project-dir <独立项目派生目录>
personal-vlog-run <项目派生目录> --presets all
personal-vlog-status <项目派生目录>
```

需要恢复时只使用 `status` 返回的本次 `run_id` 调用 `personal-vlog-resume <项目派生目录> --run-id <run_id>`。交接时读取该 run 的 `review-packet.json/md`、`edit-recipe-<preset>.json`、`mvp-v4-handoff-<preset>.json` 与缺口清单；不要只拿单个配方文件越过审核。

## 形态、筛选与声画决策

长素材先按拍摄时间、地点、动作、说话和环境声做导航；在源视频上标时间码。所有有效原件共用画面、声音、事件和覆盖分析，再按所选形态筛选；短版／轻量版不能少分析素材。日志记录技术可用、形态用途、动作／感官／信息／互动价值、声音和重复度，不用“故事推进”给所有镜头统一打分。机器未提示的区间和未用精彩候选也需复核。情绪只记录本人确认感受或可观察动作，不把机器推断写成事实。

| 主形态 | 筛选与组织依据 | 审核重点 |
| --- | --- | --- |
| 随行日记 | 实际行程、现场片段、同行互动；必要时间地点提示 | 能跟上行程、重复等待有取舍、反应真实 |
| 活动集锦 | 动作、刺激点、现场声和反应；关键动作可理解的区间 | 精彩覆盖、动作结束与反应、段落出口和速度感；慢镜头按用途保留，无固定比例 |
| 实用攻略 | 观众决定所需的信息与可核实证据 | 来源、规则日期、价格／安全／适用边界；未知留缺口 |
| 体验评述 | 明确体验维度、可见证据与本人感受 | 判断有依据；仅真实比较任务存在时比较，不强行选赢家 |
| 氛围旅拍 | 构图、环境、质感、画面运动与声场 | 感官层次和声画连续；无需旁白、冲突或高潮 |
| 现场观察 | 人物互动、生活细节、地方观察 | 真实对白、动作和语境；不编造心理 |

这是选择依据，不是固定段落公式。脚本可为镜头清单、现场提问、分段声画表或事后旁白，不必逐字口播。提前展示真实后续片段时标清时序；收尾让所选段落结束清楚，不能假装未拍到的实际旅程结束。精彩片段很多时允许增加有效段落或调整时长，不先定极短成片再淘汰内容。

现场声承担空间与行动；同期话语承担本人或受访者的原意；旁白补时间跳跃、背景和主观回看；音乐调节能量。优先保证话语可懂，再决定音乐。J/L cut、镜头长短、转场密度与节奏属于编辑选择；动作／方向连续性、信息可懂和声音不断裂是审核目标，不设通用秒数。横竖屏逐镜检查主体和文字，不把中心裁切当成适配完成。

## 两种检查权责

自动检查只报告可测量的技术状态：文件身份、完整解码、媒体参数、字幕越界／重叠、音量峰值／响度、可疑黑帧和静音。算法可以提出镜头、人物、说话人、情绪和隐私疑点，但不裁决语义或授权。

人工至少做一次整片冷看、一次手机尺寸看字与构图、一次耳机／手机扬声器听声音；再对明确风险用 VKP `targeted-review.html` 看精确范围并保存 `targeted-review-decisions.json`。审核回执只覆盖对应区间，不替代最终完整成片、隐私、版权或发布批准。改动音频、时长、字幕、源图或遮罩后，按 `docs/agent-rules/self-media-video-editing.md` 的失效图重跑下游检查。

## 证据与当前能力边界

- [Adobe 代理与原片回连](https://helpx.adobe.com/in/premiere/desktop/organize-media/ingest-proxy-workflow/reconnect-full-resolution-media-to-proxies.html)、[转写辅助粗剪](https://helpx.adobe.com/premiere/desktop/edit-projects/edit-video-using-text-based-editing/overview-of-text-based-editing.html)和 [DaVinci Resolve 官方编辑教材](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-20-Editors-Guide.pdf)支持代理、元数据、转写、字幕与交付等技术做法；故事结构与五维评分是本流程的操作性综合判断。
- [叙事连续性研究](https://doi.org/10.1111/j.1551-6709.2011.01202.x)支持关注动作与事件理解，不能推出固定镜头秒数或平台推荐效果。平台规格须按实际目的地在发布当天重查；[YouTube 上传格式](https://support.google.com/youtube/answer/4603579)及 [Meta 画幅指南](https://www.facebook.com/business/help/103816146375741)只能说明各自适用范围。以上公开资料于 2026-09-23 核验。
- 本地依据：[VKP personal-vlog-v1 交付](../../video-knowledge-pipeline/docs/personal-vlog-v1-delivery-2026-09-02.md)及 [自媒体视频编辑规则](../../docs/agent-rules/self-media-video-editing.md)。VKP `complete_draft`、三档 recipe、MVP v4 handoff 均为 `candidate_only / review_required`。既有合成测试不证明真实旅行素材已完成分析或成片。
