# 自媒体产物生命周期与大视频清理流程

## 目标

让明确失败、被淘汰和任务结束后不再需要的大视频及时退出工作目录，同时保证原始素材、精剪素材、锁定母版、发布终稿和复现配方不被自动删除。

本机制不新增渲染器、ASR、FFmpeg 状态机或发布能力，只给现有视频流程增加一层产物登记、状态转换、引用保护、可恢复隔离和到期清理。

## 固定流程

| 时点 | 必须执行 | 结果 |
|---|---|---|
| 建立项目 | `artifact_lifecycle.py init` | 建立 v2 清单；默认不授权自动永久删除 |
| 每次大渲染前 | `preflight` | 中间产物超过 2 GiB 时暂停并先做安全清理；磁盘空间按共享 `media` Profile 计算：512 MiB 硬保留、低于 5 GiB 警告、预计输出乘 1.25 倍余量 |

> 2026-08-29 策略更新：固定 15% 空闲率门已退役。小型且明确分类的任务在仅剩 2–3 GiB 时可以带警告继续；大型或未知输出必须提供预计输出字节数，否则预检关闭失败。旧 v2 清单中的 `min_free_ratio` 仅为读取兼容字段，不再参与运行判断。
| 每个产物生成后 | `register` | 记录种类、状态、大小、用途和依赖，并计算一次精确 SHA-256；若上游给出预期哈希则同时校验；≥200 MiB 必须填写保留理由 |
| QA 或人工审片后 | `transition` | 只记录 `qa_pass`、有真实原因的 `qa_fail`，或有替代目标的 `superseded` |
| 用户锁定版本后 | `lock` | 锁定选中母版；同视频保留最近一个待审候选，更老候选转为 `superseded` |
| 任务收尾 | `plan-gc --phase quarantine --task-close` | 把到期失败版、淘汰版、代理、缓存、抽帧、分块和浏览器配置列入隔离计划 |
| 人工确认计划后 | `apply-gc --phase quarantine` | 只移动到工作区内 `.artifact-quarantine`，不永久删除 |
| 发现误判 | `restore` | 原路恢复，目标路径已存在时关闭失败，禁止覆盖 |
| 保留期届满 | `plan-gc/apply-gc --phase purge` | 仅在清单授权自动清理且该产物单独批准后永久删除 |

## 保留策略

- 机器生成失败：默认保留 24 小时后才可隔离。
- 用户明确淘汰：默认保留 72 小时后才可隔离。
- 被新版本替代：默认保留 72 小时后才可隔离。
- 代理、缓存、抽帧、分块和浏览器配置：任务结束后可立即隔离。
- 原始素材、已复核素材、精剪素材、锁定母版、发布终稿和复现配方：永不自动隔离或删除。
- 默认保留当前锁定版之外最近一个待审候选，避免返工时失去可比较版本。

## 关闭失败条件

下列任一情况都不得移动或删除：

- 路径不在当前工作区根目录内；
- 清理计划对应的清单已经变化；
- 文件大小、修改时间或已登记哈希发生漂移；
- 产物仍被其他活动产物或外部配方引用；
- 属于保护种类或已经锁定；
- 未到保留期限；
- 永久删除缺少清单级授权或产物级批准；
- 隔离目标或恢复目标已经存在。

## 稳定入口

```powershell
python scripts/artifact_lifecycle.py doctor
python scripts/artifact_lifecycle.py preflight --manifest <manifest.json> --workspace-root <workspace> --output-class <small_known|large_or_unknown> --estimated-output-bytes <bytes-for-large-output> --receipt <preflight.json>
python scripts/artifact_lifecycle.py plan-gc --manifest <manifest.json> --workspace-root <workspace> --phase quarantine --task-close --receipt <plan.json>
python scripts/artifact_lifecycle.py apply-gc --manifest <manifest.json> --workspace-root <workspace> --plan <plan.json> --phase quarantine --receipt <receipt.json>
```

完整命令由 `python scripts/artifact_lifecycle.py --help` 和本地工具注册表提供。任何修改操作都写出独立回执；完整日志和清单留在磁盘，任务胶囊只传递状态和引用。

## 与现有八步案例视频路线的关系

主路线仍保持八步，不为了清理增加五个高上下文主步骤：

1. `handoff-video-owner` 内强制执行渲染前 preflight 和产物登记；
2. 客户／QA 结论产生后立即写 lifecycle transition；
3. 发布前人工门要求 exact-master lock receipt；
4. 任务结束时要求 quarantine-only 收尾计划；
5. 永久清理由以后独立的到期任务执行，绝不能和隔离操作合并。

这样既落实清理，又不突破 8 KiB 任务胶囊和八步主流程门槛。
