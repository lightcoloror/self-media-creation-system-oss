# 传播张力与情绪共鸣硬门禁

## 目的

解决一种反复出现的失败：事实正确、合规完整、句子也通顺，但内容仍像案例摘要，观众不知道为什么现在要点开、为什么要继续看，也看不见讲述者的服务究竟改变了哪一步。

这套门禁不预测“爆款”，也不奖励夸张情绪。它只阻止明显缺少观看动力的稿件过早进入 Hook、去 AI 味、拍摄和剪辑。

## 成稿前必须写出的八项

1. **人物目标或读者任务**：人物当时急着办成什么，或读者看完要解决什么。
2. **具体代价**：如果没有推进，现实中会多等什么、多付什么、错过什么或仍不确定什么。
3. **现场锚点**：一句真实对白、一个动作、一个付款节点、一张单据或一个可复现的问题。
4. **开头完成问题**：前两秒让观众等的答案是什么。
5. **至少三次信息推进**：每一次都要改变观众对事情的理解，不能用换镜头冒充推进。
6. **完成回报**：结尾明确回答开头的问题。
7. **带走价值**：观众以后能保存、转述或实际使用什么。
8. **服务因果**：转化内容必须成对写清“讲述者做了什么／现实步骤怎样改变”。

## 自动阻断条件

- 人物目标、具体代价、现场锚点、完成回报或带走价值为空；
- 开头的问题与结尾的答案是同一句改写，没有过程推进；
- 短故事少于三次不同的信息推进；
- `target_action` 为咨询或转化，却没有同时填写服务动作与现实效果；
- 成稿后仍看不见人物任务、代价、现场、完成回报或服务因果；
- 删除讲述者以后，故事仍完整成立且服务价值没有损失。

## 人工判断

程序只能确认这些问题有没有被回答，不能判断答案是否真的有力量。人工仍要判断：

- 前两秒是否让目标受众立即联想到自己，而不只是围观别人的案例；
- “代价”是否具体且由证据支持；
- 现场是否保留人的犹豫、行动和反馈，而不是全被编辑者总结掉；
- 三次推进是否真的带来新理解；
- 情绪是否来自事实，而不是恐惧放大、悲情配乐或虚构内心；
- CTA 是否只承接已经证明的能力。

## 失败后的处理顺序

1. 先换入口：从抽象主题改成现场、反常结果或具体选择。
2. 再缩小任务：一条只解决一个问题。
3. 再补服务因果：把动作放回改变发生的节点。
4. 再调整信息顺序：允许从最紧张的节点开场，再补必要背景。
5. 仍然没有张力时，改用直接解释、清单或图文，不硬写故事。
6. 结构通过后，才使用 `dbs-content`、口吻改写、`dbs-ai-check` 和 `dbs-hook`。
