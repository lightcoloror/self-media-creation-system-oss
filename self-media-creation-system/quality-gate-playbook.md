## 保险医疗客户案例的三阶段加严门

### 本轮编辑怎样开始、怎样结束

2026-10-09 18:50:58 +08:00｜Codex（GPT-6）。复用[主路由卡](../docs/content-creation-system/routing/route-card.template.md)与下方问题处理表，不增加审批或要求所有体裁套故事。

- **开始前**：引用当前稿与事实版本，确认材料可改范围；提纲阶段同步试人群处境、观看所得、暂定标题、封面文字、首句及兑现段。探索候选不等于正式 Hook／包装通过。
- **逐项改稿**：问题仍用一张表，补“本版必改／下一条验证／有依据保留”的处置。结构指出实际顺序变化；情绪指出真实阻碍与反应怎样相接、观众能多理解什么。没有新事实就不补心理、冲突或因果；没有必要修改就给具体保留理由。
- **适用观点稿**：原判断→最强合理反例→修订后边界，或说明为什么原判断仍成立。理论引用须解释实际用途和局限，不能只挂名称；不强迫故事引用理论。
- **结束本轮**：本版必改关闭、承诺可兑现且适用证据门满足后，纯偏好、更多相似候选和无依据传播猜测留到下一条验证。记录结束原因及实际投入，进入下一适用阶段；没有作者确认时仍待确认，不能替人签署。
- **投入到限仍有实质问题**：缩小范围或暂缓该稿，不以时间预算放行事实／隐私／授权问题。只有新的事实、具体作者反馈、实测发现或受影响版本变化才重开已关闭问题；不为重复风格意见重跑整链。
- **接收与效果分开**：实际改稿证明表达设计落实；目标观众复述、提问或反馈才能支持机制接收。播放、共鸣和业务结果各自待证，不用一个通过状态覆盖。

### 完成判定：检查、修改与优化分开

2026-09-17 21:32:40（Asia/Shanghai）｜Codex（GPT-6 Astra）

适用：所有本地自媒体创作与返工。复用现有流程和审核产物，不增加平行状态机或新一轮通用审批。下面是编辑执行与汇报规则；尚不是新增的程序语义校验能力。

1. **检查过，只能记检查过。** 读过Skill、填写检查表、生成故事卡或通过Schema/哈希验证，均不能单独证明正文经过优化。事实安全、结构可讲、口吻自然、观众效果分别判断，不得相互代替。
2. **发现的问题必须有处理结果。** 在当前稿的既有审查报告维护一张表：`问题及原文位置｜采用的方法/对标依据｜改前片段或顺序｜改后片段或顺序｜为何能处理该问题及可能代价｜复核结果/未解决项`。表必须指向实际正文版本，不能只写建议、意图或“已优化”。
3. **问题关闭只允许有依据的三种处理。** 已修改并逐项复核；检查后保留且说明该处为何不构成问题；因证据不足或作者明确取舍而暂缓。暂缓不等于优化完成。不能为凑改动而润色，也不能以“保持作者风格”为未处理的结构问题兜底。保留判断必须回应具体问题，不能只写“自然、完整、通过”。
4. **结构与情绪必须落在正文。** 结构复核对比实际段落顺序、冲突出现位置、信息推进和回报位置。情绪复核列出真实目标/代价/受阻动作/本人反应，以及改后哪句话让受众理解这一变化；没有真实材料就标缺口，不补哭、愤怒或内心戏。“有情绪词”不能证明有共鸣；只能报告表达已落地，观众共鸣仍待真实反馈。
5. **先处理上游，再试读和Hook。** 存在未解决的结构/情绪表达缺陷时，使用既有`return_for_revision`返回故事或角度阶段；不靠口吻修辞、作者朗读、开头方案或机器passed覆盖。作者确认事实、口吻、定稿各有具体范围，不等于替Agent完成所有内容审核。未解决的编辑工作由Agent继续，不先让作者反复试读。
6. **交付前对照原请求核账。** 逐项标明已执行且有产物、待执行、缺实际输入、不适用及理由。使用托管recipe时仍须`sequence-status --require-complete`；没有完整链就不能声称托管全流程完成。只做完文案时明确说文案阶段，未有真实媒体和发布证据不得报制作/发布/复盘完成。
7. **用户反馈可以重开问题。** 当作者指出结构或共鸣未落实，更新当前入口为返工，列出具体未关闭问题。保留旧正文与旧机器回执作为历史证据，另记不再放行的原因；不得手改生成回执，也不得因为正文哈希未变就继续使用已被内容反馈否定的编辑结论。下游从受影响处重新检查，不重做无关事实与对标研究。

最小例子：

| 问题及位置 | 实际改动证据 | 改后复核/状态 |
|---|---|---|
| 开头后背景过长、求助受阻出现太晚 | 指出完整新稿把哪段前移、哪段压缩，并展示原/新顺序 | 若只写了重排建议、正文未改，仍是待修改 |
| 找了人仍要自己查的无奈被摘要吞掉 | 用已确认的找费率表动作与“还是我自己来吧”紧邻承接 | 能解释为何该反应发生；不能据此声称观众已被打动 |
| 后来分析利弊为何意外不清楚 | 将本人纠结与对方分析在实际稿中相邻呈现 | 检查是否保留真实先后、不把后来帮助写成投保结果 |

1. Storycraft 初稿后：十一门检查中必须包含分发合规，记录内容分类、现行/未来规则、机构审核路径、账号授权路径、广告/AI标识和服务资料公开授权计划。
2. 正文和客户原声稳定后：按身份账号授权、内容依据、适当性、重要披露、客户自主隐私、追溯人工确认六道门审核，并绑定脚本哈希；只放行候选制作。
3. 精确成片发布前：绑定最终视频、平台压缩版、字幕、封面、标题、发布文案、CTA、账号、机构批准、客户最终确认、素材权利和撤回归档计划。

科普、私域、不点产品名、客户愿意正面出镜或脚本已经审过，都不自动免除后续检查。成片任何变化使旧回执失效，发布永久保持人工。

### 严肃内容的传播准备硬门

在写逐字稿前，先复用路由卡中的读者任务、开头承诺、结尾回报和看完可带走的用途。采用故事叙事时，再按 G3b 的故事条件检查人物目标、具体代价、现场或对白锚点；咨询或转化内容按下方服务动作条件检查。故事只有背景、结论和边界说明时退回结构设计；直接问答或机制解释按自身路线检查，不因没有故事情节而退回。

这不是点击率预测，也不允许为了增强张力编造情绪、对白或因果。事实本身不够支撑故事时，应换入口、改成直接解释，或暂缓发布。

## G-1：素材到选题决策门

- [ ] 素材已绑定现有 `topic-observation.v1`，没有把一则素材直接冒充最终选题。
- [ ] 同一素材至少提出三个不同争点；每个争点写明受众价值、与本篇议程的关系、证据、风险和未采用理由。
- [ ] 议程同时写清希望受众思考什么、如何理解，以及本篇唯一首要目标；没有把“操控情绪”当作目标。
- [ ] 播放潜力、新颖度和平台偏好只标为 `candidate_experience`、`agent_inference` 或 `unverified`，没有写成平台规则或固定权重。
- [ ] 高传播假设不能压过账号定位、事实证据和风险门；偏离议程、无证据冲突、伪造客户案例、评论冒充事实必须拒绝。
- [ ] `topic-angle-decision.v1` 只提出候选；人工确认选题后才进入研究和写稿，仍不授予发布或外发权限。
- [ ] 需要故事路线时，五问只映射现有 Story Design Card 的主角、目标、压力、选择代价和触发事件；不得新增未在事实卡和故事卡中的内容。

## G0：事实底座

- [ ] 每个关键结论标为：已核事实、个人经历、观点、历史发布表述或未知项。
- [ ] 标题、封面、开场没有超过正文能证明的范围。
- [ ] 数字、时间、医疗/保险判断有来源或明确为个人个案。
- [ ] 量化主张已记录地区、时期、人群、事件、时间窗、统计类型、分母、能证明什么和不能证明什么。
- [ ] 反推值保留计算和假设；压力测试没有冒充观察统计、发生概率或统一准备金额。
- [ ] 证据真假状态与当前用途分开；`retired` 证据保留退出原因且不再进入当前正文和视觉。

### G0b：科普内容加严门（适用时）

只要冻结正文包含科学、技术、健康、医学或医疗保险交叉事实主张，就在视觉或视频制作前生成 `science-popularization-review.v1`：

- [ ] 关键科学事实、数据、概念和引用已回到当前权威来源核对，并保留资料台账；AI 输出和同行内容没有被当成事实依据。
- [ ] 学术或实务争议没有被压成单一确定结论；重要局限、适用范围和个案边界在正文可见。
- [ ] 健康和医学内容已有人工专业审核；该审核不替代医生对个体的诊疗判断。
- [ ] 至少一名目标受众代表审过冻结正文，术语、结构和信息密度反馈已经处理并留有轻量证据。
- [ ] 未向 AI 输入未脱密的非公开、客户或健康资料；使用 AI 后已人工复核事实，并重新评估当前平台和机构的 AI 标识要求。
- [ ] 中国科协《科技工作者科普创作指南》仅作方法和质量依据，没有被当成保险监管、合同、医学标准或平台流量依据。

## G1：隐私与授权

- [ ] 客户、患者、儿童、家属、聊天和病历均已去标识；组合后的时间线也不会重新识别当事人。
- [ ] 受访者知道公开的渠道、用途和可识别程度；未获得授权则不用真人素材。
- [ ] 截图内没有手机号、住址、保单号、病历号、二维码、聊天记录和可定位信息。

## G2：医疗与保险边界

- [ ] 不替医生作诊疗选择，不表达某种治疗“更好/一定适合”。
- [ ] 不承诺承保、理赔、赔付比例、时效或服务结果。
- [ ] 解释合同与服务过程时，保留“具体以合同约定和实际审核为准”的适当边界。
- [ ] 没有用恐惧、疾病、家庭风险制造紧迫感；没有把个案变成万能方法。

## G3：形式与声纹

- [ ] 只有一个首要目标和一个主信息；不是把所有想讲的事塞在一起。
- [ ] 形式适配器完整：视频有口播/字幕/画面，图文一页一任务，直播有循环与预案。
- [ ] 对应 IP 的声音被保留；没有机械慢/稳/专业克制收束，也没有通用鸡汤。
- [ ] 配图复用现有视觉槽位的 `purpose`、`media_role`、`anchor`，说明每张图帮助理解什么，并对照相邻正文补充意义与条件。无需另填配图矩阵或同义字段；无贡献的重复描述可删，替代文字、图注、来源及重要限定继续保留。

### G3b：题材结构与专业距离

先复用同一张[中央路由卡](../docs/content-creation-system/routing/route-card.template.md)和既有内容对象，只补缺失项。以下条件组按当前路线启用；不适用时记理由，不为填满检查表而增加故事、改写问题或拆篇。

**通用检查**

- [ ] 已区分 `content_job`（做什么）、可选 `structure_route`（怎样展开）和 `format`（怎样被消费）；选择结构路线时以一条为主，开头承诺、正文展开和结尾回报与之相符。
- [ ] 一篇只有一个主要读者任务；只有决策型内容才要求一个决策，没有把这条规则强加给故事、机制解释或工具内容。
- [ ] 已为本条选择一种受众入口：人生问题、选择冲突、反常结果、具体损失、具体数字、身份处境、搜索意图或人工确认的其他入口；没有从抽象知识名称机械起题。
- [ ] 标题、封面和开场承诺同一件事；开场立即进入承诺，不以打招呼、自我介绍或通用定义延迟兑现。
- [ ] 需要 `content-packaging-review.v1` 的内容沿用该合同的 2–8 个有序信息推进摘录；故事另见条件组。画面切换没有冒充内容推进，不为满足次数拆碎同一信息。
- [ ] 本条交代必要上下文，兑现开头承诺，提供可理解、保存、转述或用于下一步行动的回报；结果可前置，不用空悬念或泛化口号代替答案。
- [ ] 路线所需的证据、案例、比较维度或工具输入确实存在；不存在则改道或保留待核。
- [ ] 专业度与目标受众和内容任务匹配；术语只有必要时出现并有普通话解释，重要限制不因通俗化而隐藏。
- [ ] 例外和后续问题的取舍服务于本篇目标。受众差异若会改变政策依据、合同边界或结论，则拆篇或独立分支；局部例外没有被机械拆篇。
- [ ] 若人工在中途改道，已记录受影响产物并只重跑受影响的研究问题、提纲、标题承诺和质量门。

**故事叙事（`structure_route: story-arc` 或已明确选择故事展开的案例）**

- [ ] 人物当时要办成的事、具体代价及受阻动作已经出现；至少保留一个可核验的现场、动作或对白锚点，没有用抽象风险和编辑者总结代替。
- [ ] 短故事至少有三次不同的信息推进，并在结尾兑现开头留下的完成问题；没有真实材料时标缺口或改路线，不编造情节。

**服务与保险内容（适用时）**

- [ ] 咨询或转化内容已成对写明“本人做了什么／现实中改变了哪一步”；采用故事时，删掉本人后故事不会仍然完整。
- [ ] 保险内容已明确选择“生活情境先行”或“搜索意图直接回答”，没有把“保险晚出现”机械套给所有任务。

**系列规划（`planning_scope: series`）**

- [ ] 系列拆解只用于多篇规划，每一篇仍单独选择结构路线。
- [ ] 系列中的每一条都完整交代本条的受众问题、必要上下文、核心回答和本条回报；不要求受众先看上一条，也不把本条答案留到下一条。
- [ ] 若结尾预告下一条，本条已经先兑现自己的承诺；预告的是另一个可独立成立的问题。

**问答或搜索发现内容（适用时）**

- [ ] 问答型内容已选择 `direct-answer` 或 `decision-reframe`，选择理由成立。
- [ ] `direct-answer` 已直接回答原问题，没有为了显得专业硬造另一个核心问题。
- [ ] `decision-reframe` 的原问确实遗漏关键前提；重构前已短答原问题，只向前重构一层。
- [ ] 仅 `decision-reframe` 检查：一个误区、一个关键区别、一个行动。

### 审稿职责与已有证据复用

同一版本的同一问题只在既有审查表维护一项；事实、结构、声纹或视觉角色可引用同一项，不重复计数或要求作者回答同一问题。已有任务、受众和图像用途从路由卡／内容对象读取，不重新访谈。

| 环节 | 本轮判断 | 可复用与需重查的边界 |
|---|---|---|
| 初稿与结构检查 | 内容是否完整、路线是否合适、问题是否解决 | 引用当前事实卡及问题处理表；材料、主张或作者反馈变化时重开受影响问题 |
| 作者判断与声纹 | 立场、对象、强度和口吻是否忠实 | 复用已记录的作者原话与修改原因；确认必须绑定当前正文，不能代填作者决定 |
| 包装审核 | 当前标题、封面、开场和正文是否兑现同一承诺 | 引用已完成的正文工作；包装或正文变化仍须新建精确范围审核，不能沿用旧放行 |
| 渲染与成片审核 | 实际交付是否忠实、可读、完整 | 设计稿与脚本审核不能证明渲染或成片正确，按当前产物保留检查 |

复用证据不等于跳过 `prepare-step`、输出复验、哈希核对或专业／隐私／授权门。这里整理编辑执行范围，不新增自动语义判断或自动问题关闭能力。

### G3a：内容作用机制（仅在使用时）

- [ ] 一篇最多一个主机制、一个辅机制；不用机制也成立。
- [ ] 情绪共鸣来自可观察场景；情绪强度不超过证据，不消费创伤，不强迫升华。
- [ ] 证据型槽点准确复述常见认知，有失配证据、具体成本和修正模型；没有稻草人、群体攻击或愤怒优化。
- [ ] 受众嘴替可追溯到真实问题、搜索、访谈或反馈；轻度标准化表达没有冒充逐字原话。
- [ ] 行动型价值认同包含真实决策、合理选项、取舍、行动和后果；没有道德优越或强迫站队。

发布前使用 `publication_release`；人工上传后使用 `publication_post_upload`。后者允许发布前状态为 `pending`，但正式结案时六项上线后检查必须全部通过。两个校验器只校验和留痕，不得上传、换源、删除或发布。

定时发布门必须以“当前实际提交时间”为计算基准，同时保存平台已确认的最短提前量和最远可选时间。长期发布日历可以超过平台窗口，但超出窗口的条目只能标为计划，不能标成已经设置定时；进入窗口后再滚动设置。当前确认的快手最远窗口为 12 天，规则来源状态为 `user_confirmed_current_authenticated_ui_2026-08-28`。

### 上线后纠错路线

- 必须记录“当前账号＋当前作品”的实测能力，不把一次界面结论写成永久平台真理。
- 可换源：保留原发布事件，换源后重新记录 edited 和上线后六项检查。
- 不可换源：删除前先保存展现、互动、实际发布时间和原内容ID；旧事件记为 deleted，重发后创建新 published 事件。
- 能力不明或仅条件支持：停在 manual_triage，到当前登录界面复核，不自动删除或重发。

### 变更后的失效范围

- 事实或脚本改变：第2—11步失效。
- 音频或剪辑点改变：第5—11步失效。
- 画面、打码、人脸归属或冻结问题改变：第6—11步失效，客户确认随候选哈希失效。
- 仅标题、封面、简介、标签或合集改变：只重跑第10—11步。
- 仅某平台规则改变：只重跑该平台第10—11步。
- 上线后纠错：原则上只重跑该平台第10—12步；如果修改了内容本体，再按上述范围扩大。
