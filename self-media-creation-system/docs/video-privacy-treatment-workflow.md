# 视频变声、打码与发布前局部返工操作卡

> 更新时间：2026-08-28 12:08:00 +08:00
> 执行者：Codex（GPT-5.6 Sol）  
> 适用 Recipe：`case-video-candidate`  
> 发布边界：manual-only

## 一、素材进入时

准备以下本地引用，不把大文件或客户身份写进任务胶囊：

- 原素材及 SHA-256；
- 匿名人物清单 `subject_manifest`；
- 人物角色与身份参照清单 `identity_reference_manifest`；
- EDL／时间线；
- 说话人分段；
- 人脸轨迹；
- 每个人物实际出现在最终画面中的窗口清单 `visible_window_manifest`；
- 马赛克、变声和动效配方目录。

人工为每个 `subject_ref` 填写两项决定：

| 处理项 | 可选动作 | 说明 |
|---|---|---|
| 声音 | `keep_original` / `convert_same_gender_range` / `mute` / `exclude_segment` / `undecided` | 变声必须引用本地同性别、相近音域配方；粤语优先同方言并保留 F0 |
| 面部 | `keep_visible` / `mosaic` / `exclude_front_face` / `undecided` | 马赛克必须引用已由人工绑定到该人物的人脸轨迹配方 |

规则：

- 全部明确：`customer_choice_status=confirmed`、`preview_policy=customer_preview`。
- 任一未定：`customer_choice_status=undecided`、`preview_policy=internal_preview_only`。
- 未定状态可以继续制作内部预览，但不能进入人工发布交接。
- 人脸检测只能证明“这里有一张脸”，不能证明“这就是受访客户”。人工必须先用匿名身份参照把人脸轨迹绑定到 `subject_ref` 和角色；未确认身份时一律失败关闭。
- 一个面部轨迹不能同时分配给两个人物；目标客户与采访者／创作者必须分别标注。
- 打码起止时间以最终画面中人物真正出现和离开的帧为准，不得只沿用采访音频、脚本段落或粗剪片段的起止时间。

决定合同：[`video-privacy-treatment-decision.v1.schema.json`](../schemas/video-privacy-treatment-decision.v1.schema.json)。

## 二、客户看完候选后

由人工把客户结果记录为：

- `confirmed`：确认当前候选；
- `request_changes`：列出人物、变更种类和精确起止秒数；
- `withdrawn`：撤回，不再推进。

记录必须同时绑定：

- 当前候选文件 SHA-256；
- 当前人物处理决定文件 SHA-256；
- 候选时长；
- 变更窗口和本地配方引用。
- 当前候选的隐私渲染质检记录；
- 每个目标人物、每个实际可见窗口的五点检查结果。

不要存客户身份和原话，只存操作所需的短摘要。系统本身不联系客户。

每个可见窗口的五点检查固定为：

1. 人物进入前一帧：非目标人物没有被误打；
2. 目标人物第一帧：已经正确打码；
3. 窗口中点：转头、侧脸或遮挡时仍覆盖；
4. 目标人物最后一帧：仍然正确覆盖；
5. 人物离开后一帧：非目标人物没有继续被误打。

最终候选还必须给出两个整片结论：`target_faces_complete=true` 与 `non_target_faces_unaffected=true`。任何一个为假、任何可见窗口缺记录、第一／中间／最后一帧未通过，均不得进入客户确认或发布门。

如画面还需显示“受访者已确认并授权本次采访、出镜及发布”，该授权提示必须与被授权人物的实际可见窗口同步。没有客户画面的区间不得错误显示；有客户画面的区间不得漏显示。授权提示不能替代书面授权，也不能证明打码对象正确。

客户审核合同：[`customer-video-effect-review.v1.schema.json`](../schemas/customer-video-effect-review.v1.schema.json)。

## 三、发布前本地判定

```powershell
python scripts/video_privacy_treatment.py evaluate --decision <decision.json> --review <review.json> --workspace-root <media-workspace> --output <gate.json>
```

输出只有四种状态：

| 状态 | 含义 | 后续 |
|---|---|---|
| `internal_preview_only` | 仍有未定处理项 | 留在内部，不发布 |
| `customer_confirmed_candidate` | 明确决定和客户确认都绑定当前候选 | 可交独立人工发布门 |
| `limited_rework_required` | 客户要求改动 | 只重做列出的时间窗 |
| `withdrawn` | 客户撤回 | 停止 |

判定合同：[`prepublication-privacy-gate.v1.schema.json`](../schemas/prepublication-privacy-gate.v1.schema.json)。

## 四、临时变更如何局部替换

`limited_rework_required` 会输出：

- `changed_windows`：需更换的精确秒数、人和处理类型；
- `frozen_scope=all_unlisted_windows`：其他片段保持不动；
- `local_edit_state`：原 EDL、分段、轨迹和三个配方目录；
- `downstream_invalidations`：只需重验的锁和质量门；
- `review_interface`：固定为 VKP `targeted-review`。

典型失效范围：

| 客户变更 | 只使这些部分失效 |
|---|---|
| 变声 | audio lock、响度、字幕时序、包装、最终审片 |
| 面部／马赛克强度 | picture lock、隐私、保护区域、包装、最终审片 |
| 动效 | picture lock、动效时序、保护区域、包装、最终审片 |
| 删除／替换片段 | 时间线、音画锁、响度、字幕、动效、包装、最终审片 |

完成局部替换后必须：更新人物处理决定版本 → 用 VKP 审确切窗口 → 生成新候选哈希 → 重新获得客户确认。旧确认不得沿用。

## 五、变声配方约束

最终交付建议使用：同语言、同方言、同性别与相近音域的目标音色；开启 F0 conditioning 或等效的音高／语调保留；参考音采用 10–30 秒干净自然语音。粤语、越南语等声调语言要额外检查声调和语气；中英混说、方言、快速讲话和重情绪片段要逐窗试听。

跨性别或跨方言变声可以作为内部技术探针，但不应成为默认客户候选。

## 六、验收清单

- [ ] 每个人物至少关联说话人分段或人脸轨迹。
- [ ] 每个需打码人物均已确认匿名角色、身份参照和人脸轨迹绑定关系。
- [ ] 客户、采访者／创作者及其他人物没有共用同一人脸轨迹。
- [ ] 可见窗口按最终画面帧确定，不以音频或脚本时间代替。
- [ ] 未明确时只生成内部预览。
- [ ] 变声使用同性别、相近音域配方并保留 F0。
- [ ] 马赛克配方覆盖正脸、侧脸、转头和短暂遮挡。
- [ ] 每个可见窗口的进入前、第一帧、中点、最后一帧、离开后五点检查齐全。
- [ ] 所有目标脸无遗漏，所有非目标脸无误伤。
- [ ] 授权提示与客户实际出镜窗口同步；不适用时明确记录 `not_applicable`。
- [ ] 客户结果绑定决定哈希与候选哈希。
- [ ] 临时变更只列受影响窗口，未列窗口冻结。
- [ ] 局部重做后重新走 VKP 时间段审片和客户确认。
- [ ] 局部重做窗口已用 `video-window-motion-gate.ps1` 比较返工前后运动状态；未引入意外冻结。
- [ ] 合法停帧已在视觉计划中预先声明，人物镜头的真实切镜前后已逐帧检查。
- [ ] 最终仍由人工决定是否发布。

## 七、错误版本与返工边界

- 一旦发现打错人物、漏打某个可见窗口或误伤非目标人物，当前候选立即标记为 `rejected`，不得继续作为客户审片或发布候选。
- 返工必须从锁定的无打码母版或对应独立人物素材重新生成，不在错误成片上叠加第二层马赛克掩盖问题。
- 修复身份绑定、轨迹或窗口后，原候选哈希、隐私质检、客户确认和发布前隐私门全部失效；字幕、音频和无关画面可在哈希和冻结范围一致时继续复用。
- 合格候选只保留一个“当前版本”指针；错误版和中间版集中放入待清理区，名称必须含 `rejected` 或 `superseded`，防止误发。
- 返工后必须在每个变更窗口比较返工前源片与新候选的冻结事件。源片无冻结而新候选新增 `>=0.75 秒` 的人物画面冻结时，当前候选失败关闭；文件能解码、音频校验一致或总时长不变均不能豁免。
- 静态截图、证据停留和设计停帧只有在视觉计划中预先声明精确时间与用途时才可豁免；人物采访或口播不得事后声明为静态画面。
