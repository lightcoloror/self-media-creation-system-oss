# 质量闸门操作卡

> 所有闸门都在人工发布前执行。任何“待核”都可以让内容停在草稿，不应靠更好看的表达掩盖。

## 初稿出来后的固定顺序

```text
原始资料 → 唯一事实卡锁定
→ 路由卡 / 单条脚本卡
→ 可选结构对标与视觉职责映射
→ Storycraft 初稿
→ 初稿十一门检查
→ 全部通过后才进入 dbs-content / dbs-ai-check
→ 实际口吻改写
→ 作者朗读与确认
→ 冻结正文后生成 Hook
→ 严肃内容误读、边界、安全与趣味完整性后检（适用时）
→ 多平台事实一致性复核（存在两个以上平台版本时）
→ 最终高风险审核
→ 试拍、成片确认与人工发布
```

不能在事实卡未锁定时直接写 Storycraft，也不能从初稿直接跳到标题、Hook、去AI味或试拍。事实、任务和服务因果未通过时，润色只会把错误写得更顺。

## 严肃内容翻译双门

保险、健康、高风险内容，以及明确声明为严肃专业内容的稿件，在成稿前先记录受众决定、证据底座、隐私状态、风险边界、生活关联入口、趣味强度与信息推进；普通内容可以明确记为 `not-applicable`。敏感度还要细分为普通、专业敏感、医疗敏感、当事人重病、客户损失、隐私高风险或复合高敏感。当事人重病、客户损失、隐私高风险和复合高敏感默认不加幽默；轻度幽默也要有人工作出的明确例外，且不能把受影响的人当作笑点。正文完成人声改写并冻结后，再绑定正文 SHA-256，检查关键边界是否在正文中、来源细节是否仍在发布包、是否给出安全行动、是否把个案泛化，以及观众最可能怎样误读。

成稿前还必须写清：人物当时急着完成的目标或读者当前任务、可以落到画面或对白的现场锚点、观众会付出的具体代价、开头留下的完成问题、结尾实际交付的完成回报、看完可以带走或继续使用的内容。若目标是咨询或转化，还必须成对记录“讲述者做了什么”和“这个动作具体改变了哪一步”；不能只展示客户遭遇，也不能只写“专业陪伴、全程协助”。短故事从开头到结尾至少有三次不同的信息推进，只有“提出问题—马上回答”不算完整推进。

这些字段是最低结构合同，不是“爆款分数”。系统不对情绪浓度、冲突强度或点击率做平均分，也不允许为了过门禁虚构对白、内心或风险；缺少真实张力时，应换题、缩小承诺或改用直接解释型结构。

两段记录最终汇入同一个 `serious-content-translation-review.v1` 回执。只要用了幽默、视觉梗、趣味类比或其他娱乐手段，还必须逐项确认：它是否帮助回答正文核心问题；对象是否安全；去掉后事实和服务价值是否仍成立；观众主要记住的是核心判断、动作或机制，而不是梗。趣味只能标为 `related` 才能通过；`decorative` 和 `misleading` 均退回修改。保险健康及高风险内容的证据、边界、安全三项均不得低于 4/5；回执只允许 `candidate-only / review-required / manual-only`，不能代替作者确认、机构审核或发布授权。

## 多平台事实一致性门

同一内容形成两个以上平台版本后，不能仅分别审每一版。所有版本必须绑定同一事实卡修订版和同一标准化主张账本，再运行 `cross-platform-fact-consistency-review.v1`：核心主张全部保留且文本哈希一致；非核心主张只可因版面密度、内容形态或时长省略，并写明理由；任何新增未申报主张、混用事实修订版、平台正文哈希漂移或回执过期均阻断。平台版本可以改变措辞和结构，但事实主张不能随平台改变。

## 初稿十一门检查

| 顺序 | 闸门 | 必须回答的问题 | 不通过时 |
|---|---|---|---|
| D0 | 事实与证据 | 是否绑定唯一事实修订版；每个关键句对应哪个事实 ID；量化主张的地区、时期、人群、时间窗、统计类型和分母是什么；这个数字回答什么、不能回答什么；反推假设、证据当前用途及最新纠错是否已记录？ | 待核、事实源未锁定、旧修订仍在引用，或用不匹配的数字替代目标问题时阻断；其余退回修改 |
| D1 | 单条任务 | 是否只有一个主要读者任务、一个受众和一种服务能力？受众差异是否会改变政策依据、合同边界或结论；若会，是否已经拆篇或独立分支？ | 退回拆题或明确分支；不能把“一篇一个决策”强加给非决策题材 |
| D2 | 服务因果 | 客户困难负责吸引人以后，能否看见本人做了什么、改变了哪一步、不能保证什么？ | 退回重写；不得只剩客户故事 |
| D3 | 采访完整性 | 原声是否回听校字、保留提问背景、不拼接表扬，只证明本人经历？ | 无授权或改变原意时阻断 |
| D4 | 分发合规 | 内容性质、现行/未来规则、机构审核、账号授权、广告与AI标识是否已记录？是否错误地把科普或私域当成豁免？ | 缺路由或误判时阻断 |
| D5 | 医疗与保险 | 是否越过医疗决定、治疗优越性、保单适用范围、赔付承诺或服务收费边界？ | 阻断 |
| D6 | 隐私与授权 | 服务资料二次使用、受访者与患者授权、正脸原声及健康理赔范围、重识别风险、撤回和最终成片确认是否清楚？ | 阻断 |
| D7 | 标题与开头 | 标题、开头、正文和CTA是否兑现同一个承诺，前五秒是否具体且不卖恐惧？ | 退回修改 |
| D8 | 口语与AI痕迹 | 是否仍有舞台化转折、整齐排比、抽象自夸、统一节奏和嘴上说不出的句子？ | 退回口吻处理 |
| D9 | CTA与产品 | CTA是否只承接已证明的服务，并说明免费、协议内与另行收费的边界？ | 转化内容退回修改；非转化内容可标不适用 |
| D10 | 制作与系列 | 单条能否独立听懂，与相邻条是否重复；对标是否只学结构而没有导入事实；讲述者、客户、证据和信息卡是否分工；关键事实是否有手机可读的画面；时长、删句和单变量是否明确？ | 退回制作准备 |

固定反向测试：删掉讲述者及全部服务动作后，故事是否仍然完整？如果完整，这通常只是客户经历，不足以证明服务价值。

固定完播测试：遮住标题后，只听前两秒，能否说出“谁现在要办成什么、卡在哪里”；听到中段时，是否至少已经发生一次行动反馈而不是继续补背景；听完后，开头留下的问题是否得到一个具体回答。任一项答不上来，先退回结构修改，不进入 Hook 润色。

## 初稿状态合同

- `approved_for_voice_pipeline`：所有适用闸门通过，才能进入内容诊断、口吻改写和后续 Hook。
- `return_for_revision`：至少一门需要修改但没有红线阻断；改完以后必须重新审核并生成新回执。
- `blocked_from_downstream`：事实、医疗保险、隐私授权或采访完整性存在阻断；不得继续去AI味、Hook、试拍或发布。

`case-video-initial-draft-review.v1` 同时绑定初稿正文哈希和 `input_fact_card_ref`。正文或事实卡修订版任一变化，原回执自动失效，必须重新检查。人工改题、改受众、改结构或替换证据时，在现有 `manual_route_override` 和 `qa.deterministic` 中记录受影响产物与需要重跑的门；不要求重跑无关环节。机器只验证十一门是否完整、状态是否自洽和版本绑定是否一致；事实判断、医疗保险边界、分发合规、隐私和口吻仍由人负责。

## 稳定脚本与成片的合规门

- 稳定脚本：按身份账号授权、内容依据、适当性、重要披露、客户自主隐私、追溯人工确认六道门审核，只放行候选制作。
- 精确成片：绑定最终视频、平台压缩版、字幕、封面、标题、发布文案、CTA、账号、机构审批、客户最终确认、素材权利和撤回归档计划。
- 脚本审核不继承为成片审核；任一受审内容变化都使旧回执失效。

## G0：事实底座

- [ ] 每个关键结论标为：已核事实、个人经历、观点、历史发布表述或未知项。
- [ ] 标题、封面、开场没有超过正文能证明的范围。
- [ ] 数字、时间、医疗/保险判断有来源或明确为个人个案。
- [ ] 每个量化主张已记录地区、时期、人群、事件、时间窗、统计类型、分母、能证明什么和不能证明什么。
- [ ] 反推值写明公式与假设；压力测试明确不是观察统计、疾病预测、发生概率或统一建议。
- [ ] 证据的核验状态与当前用途分开；退出正文的证据保留 `retired` 原因，不再被视觉或标题误用。

## G1：隐私与授权

- [ ] 客户、患者、儿童、家属、聊天和病历均已去标识；组合后的时间线也不会重新识别当事人。
- [ ] 受访者知道公开的渠道、用途和可识别程度；未获得授权则不用真人素材。
- [ ] 截图内没有手机号、住址、保单号、病历号、二维码、聊天记录和可定位信息。

## G2：医疗与保险边界

- [ ] 不替医生作诊疗选择，不表达某种治疗“更好/一定适合”。
- [ ] 不承诺承保、理赔、赔付比例、时效或服务结果。
- [ ] 解释合同与服务过程时，保留“具体以合同约定和实际审核为准”的适当边界。
- [ ] 没有用恐惧、疾病、家庭风险制造紧迫感；没有把个案变成万能方法。

## G3：形式与声纹

- [ ] 只有一个首要目标和一个主信息；不是把所有想讲的事塞在一起。
- [ ] 形式适配器完整：视频有口播/字幕/画面，图文一页一任务，直播有循环与预案。
- [ ] 使用外部对标时，已记录采用项、拒绝项和适用分镜；外部案例没有进入本地事实卡。
- [ ] 客户原声只证明亲历和感受，原件只证明实际载明内容，信息卡只帮助理解。
- [ ] 对应 IP 的声音被保留；没有机械慢/稳/专业克制收束，也没有通用鸡汤。

## G4：权益、可访问性与发布

- [ ] 图、音乐、引文、界面、客户素材的来源和授权可说明。
- [ ] 进入视觉制作前已确定证据采用直接截图、裁切、重绘、只引用还是只链接，并记录页码、许可和署名要求。
- [ ] 字幕经过人工核对；信息不只靠颜色传递；手机上可读。
- [ ] 最终文本、图片/视频版本冻结；用户本人确认后才发布。
- [ ] 发布后再记录账号、平台、时间与版本；不把“无人互动”解读为失败。

## 加严规则

| 内容 | 必须额外确认 |
|---|---|
| 理赔/诊疗案例 | G0、G1、G2 全部逐项通过；先确认公开范围，再选择叙事角度 |
| 图语家 / AAC Demo | 真实功能、演示模拟、未来计划三者清楚区分；无障碍可读性优先 |
| 亲子与情绪工具 | 不把一般建议包装为治疗或唯一正确做法；危险情形保留求助边界 |
| 朋友圈 | 不以缺少数据为由补造反馈；图片只记轻量描述即可 |

## 框架决策接入（2026-10-10）

更新：2026-10-10T09:28:29+08:00；Codex（GPT-6）。完整操作见[四种框架决定](../../../self-media-creation-system/topic-reframing-playbook.md#内容框架决定在结构故事和正式包装之前)。

写作前比较每个候选对应的受众、观众所得、具体商业关系、材料兑现和制作成本；不是只给商业关联标高/中/低。使用 `topic-angle-decision.v2`，允许继续、重构、补材料、暂缓，允许全部不选。只有已确认且材料仍有效的继续决定进入结构/故事/初稿。补材料仅通往指定研究或素材准备；重构必须实际改稿并重新评估；暂缓保留材料和恢复条件。已知方向的局部改动可复用仍有效的判断，不重复全面探索。

前置 `dbs-content-value` 诊断与 `dbs-title-cover-intro` 的联合框架探索；正式标题/封面文字/开头仍在正文稳定和适用人工确认后。`title-matrix` 作为同一条标题流程的比较工具；旧 `dbs-hook` / `dbs-xhs-title` 仅兼容，不默认重复调用。新Skill不能代替事实核验、作者决定和改稿。

写后必须再次定位承诺的实际兑现段落。没有实际改稿和差异证据，只能记录已检查；框架失败退回重构，不能靠口吻、情绪词或换标题关闭问题。v1旧角度回执不自动升级为此项完成。
